# Tianwen v0.1.0 Research Preview

**Status:** reviewed release candidate; no tag or GitHub Release has been
created

**Date:** 2026-08-20

## Problem

An Agent can complete one session without answering the longer-lived
governance questions: what evidence supports the result, whether a problem is
repeated and attributable, and whether a future change has been independently
shown to be better. Tianwen explores a learning control plane for those
questions without replacing the Agent that performs the current task.

This is deliberately a research preview. It publishes a small, reproducible
execution-and-Evidence result and its limits; it does not claim that autonomous
learning is complete.

## One Runtime and one learning control plane

DSH 0.1.0-rc.7 is the only product Agent Runtime. It owns the current Agent
loop, models and providers, tools and MCP, sandbox, Session and Session Query,
Skill, Jobs, Workflow, Subagent, Message Feedback, Approval, and permissions.

Tianwen is the non-interfering learning control plane around that Runtime. Its
product boundary covers cross-run Goal Graph, Evidence provenance, learning
attribution, and future-run version governance. In this preview, the exercised
Tianwen path is intentionally narrower: it reads a completed DSH Session and
projects Evidence without modifying the execution record.

DSH Message Feedback may be an attribution input; it is not a Lesson by
itself. A DSH Job is process-local work; it is not a durable cross-run Learning
Ticket. Alpha remains an experiment and evaluation lab, not a second product
Runtime. See the [architecture overview](../tianwen-architecture-overview-v2.md)
for the detailed ownership boundary.

## What this preview proves

The deterministic demo uses the normal DSH Agent loop with two scripted model
responses and one deterministic `summarize` tool call. The turn completes,
Tianwen projects one complete Evidence record, and the DSH session-event digest
is identical before and after projection within the same run.

The demo intentionally supplies no repeated failure or user correction. Its
learning result is therefore zero qualifying signals, `no-case`, and
`candidateCreated=false`. No Case or Candidate is manufactured from one
successful run.

The demo uses no network, Provider, paid model, token budget, Docker service,
persistent database, or user data. The rc.7 dependency closure, public reuse
surface, types, Evidence behavior, and product Runtime composition are covered
by separate stable gates.

## Reproduce

Install the frozen dependencies and run the zero-cost demo:

```console
pnpm install --frozen-lockfile
pnpm demo:research-preview
```

The command prints one formatted JSON object. Expect a completed execution,
two scripted model requests, one tool call, one complete Evidence record,
`no-case`, `candidateCreated=false`, and matching `beforeDigest` and
`afterDigest`. Digest values may vary between separate runs because events
contain run-specific data; equality within one run is the non-interference
claim.

The local zero-paid verification set is:

```console
uv sync --frozen --dev
uv run ruff check .
uv run python -m compileall -q src tests
uv run pytest
pnpm run typecheck
pnpm run check:dsh-install
pnpm run check:no-private-dsh-imports
pnpm exec vitest run --exclude tests/dsh-migration/runtime-profile.spec.ts
```

## Existing Alpha/DSH evidence assets

- Alpha A1–A5 task packages and real-sequence results preserve bounded task,
  evidence, recovery, and cost observations.
- Alpha-B preserves paired comparison methodology and three-valued evaluation
  outcomes.
- Alpha-C and Alpha-C Intake preserve learning-intake, no-Case, and
  no-Candidate evidence.
- DSH compatibility and rc.7 product gates preserve the public seam,
  dependency-closure, Agent, Goal, Session, Evidence, and Runtime-composition
  findings used by the current architecture.

These are research and evaluation assets, not user adoption, production usage,
or evidence that the old Python Runtime should return. A1–A5, Alpha-B/C, and
Alpha-C Intake do not demonstrate Stars, downloads, external contributors, or
deployed customers. Alpha-D remains stopped and is not part of this preview.
The repository retains executable Python `RepoTaskRuntime` / `AlphaRuntime`
experiment code so the historical evidence and regression tests remain
reproducible. That frozen lab code is not a supported product Runtime, and
this preview does not publish it to PyPI or npm.

## Known limitations

- Candidate generation is not complete.
- Shadow evaluation is not complete.
- Promotion and future-run Champion switching are not complete.
- There is no production SLA or complete user interface.
- The preview does not demonstrate a full continual-learning loop or broad
  improvement across tasks.
- The legacy `tests/dsh-migration/runtime-profile.spec.ts` subprocess
  diagnostic remains excluded from release gates because it can hang during
  first-profile bootstrap. It is not reported as passing and is not evidence
  of an rc.7 API failure.
- The repository remains private and this candidate has no tag or GitHub
  Release until the user separately confirms the external actions.

## Roadmap

The next product work is to connect the proven Evidence seam to a cross-run
Goal, then add a non-blocking durable learning intake. Only a real, repeatable,
attributable problem should justify implementing the smallest Candidate path.
Independent evaluation, Shadow, Promotion, and rollback must affect future new
runs only; the current run must never hot-swap.

This roadmap is a design direction, not a statement that those capabilities
already exist.
