# 天问产品与自动学习的固定范围（2026-09-28）

## 结论

天问已有交付中的 `0.1.22` / Desktop `preview.23` 研究预览产品，普通任务能力不是从零等待验收。当前的 **NO-GO** 指向下一次把开发分支整体合入主线、升级日常安装，以及宣称“自动学习已能可靠改善未来任务”；它不撤销现有预览版的交付事实。三个对象今后分别报告，不能再用自动学习未完成概括为“项目没有产品”。

| 对象 | 当前状态 | 本轮结束条件 |
| --- | --- | --- |
| 现有研究预览产品 | `0.1.22` 已交付；普通真实任务可运行，但不保证每次答案正确 | 保留现有版本、使用说明和已知限制；普通任务的新问题按实际影响处理，不要求先产出新方法 |
| 独立安全维护 | [PR #1](https://github.com/daydreamer0213/Tian-wen/pull/1) 已隔离新方法激活，四项 CI 与独立只读代码审查通过；现可审查，尚未合入或安装 | 沿用既有主线合入门槛；如决定合入，再核对准确主线 CI、安装备份、旧数据保护和启动检查。不能把 PR 的通过写成 Daily 已更新 |
| 完整自然自动学习 | 真实反馈、研究及试验多次到达，但语义漏判、研究未采纳或新案例生成失败使新方法收益尚无可靠前瞻证明 | 仅在全新自然证据实际走到相应阶段时，分别报告普通任务、反馈归因、研究裁决、独立语义安全、激活和后续任务效果；没有合格 `accepted` 就如实记录未触发，不重跑旧样本或降低原门槛 |

## 范围和停止条件

1. 下一阶段的开发先以现有项目待办作为普通工作输入。真实模型完成有用任务本身是产品证据；只有用户自然给出可归因的读后反馈且同意有效，才继续观察学习链。受控预编排材料可以验证机制，不能代替真实任务效果或外部用户长期使用。
2. PR #1 是安全维护候选，不包含开发分支另外 272 个提交。它保留 `accepted` 裁决但暂停**新的**方法激活，历史激活仍回放；因此它减少未来误采用风险，却不证明研究审核正确，也不自动消除历史已生效方法。现有日常包仍为旧版，不能依据 PR 的代码声称日常已受保护。
3. `learningLoop.enabled: true` 配置的是特定受控学习执行器，并非所有自然学习入口的总开关；自然分析另受当前有效同意约束。不能只翻转这一项配置就宣称已拆出“纯普通任务版”。若要改变普通任务观察或反馈功能，须作为独立产品变更设计和验收。
4. 不为追求某个通过次数添加新的通用质量版本、第三位评审、题目重试或写作禁令。遇到可复现的证据错连、越权激活、旧数据改写等产品边界错误，做最窄修复；遇到单次模型回答质量问题，保留失败和责任归属。新增发布条件只在出现新的、可指认的用户伤害或安全边界问题时提出，并明确其改变了哪项既有门槛。
5. 用一个最多十个工作日的收口窗口作下一次**决策**，不把十天承诺为自动学习完成时间。窗口结束时按上述三个对象给出“已有交付／可独立维护／研究继续或停止”的明确判断和剩余证据，而非自动开启下一轮同类样本。完整自动学习若仍无合格方法及后续效果，就继续标研究未通过；这不重新打开已交付预览产品的验收。
