# 天问产品与自动学习的固定范围（2026-09-28）

## 结论

天问已有交付中的研究预览产品；安全维护后日常版本为 `0.1.23` / Desktop `preview.24`，原 `0.1.22` / `preview.23` 是历史交付。普通任务能力不是从零等待验收。当前的 **NO-GO** 指向把完整自动学习开发分支合入主线或宣称“自动学习已能可靠改善未来任务”；它不撤销预览产品和独立安全维护的交付事实。三个对象今后分别报告，不能再用自动学习未完成概括为“项目没有产品”。

| 对象 | 当前状态 | 本轮结束条件 |
| --- | --- | --- |
| 现有研究预览产品 | 日常 `0.1.23` 已交付；普通真实任务可运行，但不保证每次答案正确 | 保留现有版本、使用说明和已知限制；普通任务的新问题按实际影响处理，不要求先产出新方法 |
| 独立安全维护 | [PR #1](https://github.com/daydreamer0213/Tian-wen/pull/1) 和 [PR #2](https://github.com/daydreamer0213/Tian-wen/pull/2) 已合入并通过准确主线 CI；受管、Web 与桌面日常安装已核对，详见[023 交付](tianwen-safety-023-delivery-20260928.md) | 维护交付已完成；后续仅对实际新问题按影响处理，不借此宣布完整自动学习通过 |
| 完整自然自动学习 | 真实反馈、研究及试验多次到达，但语义漏判、研究未采纳或新案例生成失败使新方法收益尚无可靠前瞻证明 | 仅在全新自然证据实际走到相应阶段时，分别报告普通任务、反馈归因、研究裁决、独立语义安全、激活和后续任务效果；没有合格 `accepted` 就如实记录未触发，不重跑旧样本或降低原门槛 |

十个工作日窗口是**作决定**的期限，不是保证自动学习成功的工期。若窗口内仍无新研究被有效裁决、独立语义审查和合格后续效果，就明确记录“完整自动学习未通过，继续研究或停止”，不再以增加评审人数、反复出同类题或提高通过次数延长验收。若真实工作自然产生有效反馈，才按原有来源资格、研究、独立审查和未来效果顺序前进；任一环节失败即保留原结果并停止该轮。

## 范围和停止条件

1. 下一阶段的开发先以现有项目待办作为普通工作输入。真实模型完成有用任务本身是产品证据；只有用户自然给出可归因的读后反馈且同意有效，才继续观察学习链。受控预编排材料可以验证机制，不能代替真实任务效果或外部用户长期使用。
2. PR #1 与发布用 PR #2 仅交付独立安全维护，不包含开发分支的其他自动学习实验提交。它保留 `accepted` 裁决但暂停**新的**方法激活，历史激活仍回放；因此它减少未来误采用风险，却不证明研究审核正确，也不自动消除历史已生效方法。日常 023 已安装并核对，具体证据见交付记录。
3. `learningLoop.enabled: true` 配置的是特定受控学习执行器，并非所有自然学习入口的总开关；自然分析另受当前有效同意约束。不能只翻转这一项配置就宣称已拆出“纯普通任务版”。若要改变普通任务观察或反馈功能，须作为独立产品变更设计和验收。
4. 不为追求某个通过次数添加新的通用质量版本、第三位评审、题目重试或写作禁令。遇到可复现的证据错连、越权激活、旧数据改写等产品边界错误，做最窄修复；遇到单次模型回答质量问题，保留失败和责任归属。新增发布条件只在出现新的、可指认的用户伤害或安全边界问题时提出，并明确其改变了哪项既有门槛。
5. 用一个最多十个工作日的收口窗口作下一次**决策**，不把十天承诺为自动学习完成时间。窗口结束时按上述三个对象给出“已有交付／可独立维护／研究继续或停止”的明确判断和剩余证据，而非自动开启下一轮同类样本。完整自动学习若仍无合格方法及后续效果，就继续标研究未通过；这不重新打开已交付预览产品的验收。
