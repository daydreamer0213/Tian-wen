# 学习状态公开新方法激活暂停策略（2026-09-30）

## 已修复的产品信息缺口

运行包已经在账本和研究循环中隔离新的对话指导方法激活，但 `tianwen_learning_status` 原先只展示同意、研究裁决和当前生效数量。用户查询学习进度时，无法从这个只读工具得知当前新激活被暂停；研究 `accepted` 与未生效之间的原因不完整。

开发分支现增加 `conversationGuidanceActivation`：`quarantined` 直接读取执行新激活写入检查的账本配置，不根据研究数量推测，也不再复制一份开关到状态服务。说明明确区分新激活被拦、历史激活未被这项隔离自动撤销、分析及研究仍受各自同意和证据规则约束；`false` 只表示没有这项隔离，不表示激活已获准。工具说明要求回答时把这项策略与同意和研究数量分别说明。

## 验证与边界

- 新定向测试先因缺少策略字段失败；实现后，实际核心运行服务在隔离开启和关闭时均返回对应值，即使没有研究也能说明策略。已有历史研究统计测试同时保留 `accepted` 和当前生效数量，避免把暂停新激活说成已清除历史方法。
- 学习同意、指导账本和研究循环三组测试 **207/207** 通过；八个 TypeScript 包构建／类型检查和差异检查通过。只读状态检查确认账本字节、同意内容和模型请求数量不变。
- 重新构建正式 `runtime.js` 后，直接挂载其真实产品服务并执行状态工具，得到 `quarantined:true`、同意关闭、研究零条、账本无变化、模型请求零次。收据在 `D:/DevData/tianwen-quarantine-status-20260930/built-status-receipt.json`，运行文件 SHA-256 为 `0e6bff322b91bef806ebd35c6c96b0364569e03d735923dff68ff57cfb722566`。
