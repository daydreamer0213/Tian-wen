## 卡点与准确边界

1. **普通任务的真实反馈不能自动转化成可修改的 Skill。** 本次分析拥有用户反馈与会话背景，但可引用 Evidence ID 列表为空，冻结的源 Skill 不存在，因此拒绝生成 Candidate。不是说用户指出的问题不存在，也不是试点研究材料不够就能解释这个停止原因。当前聊天纠错有效，长期 Skill 改进没有发生。
2. **主对话对学习状态的说明不够可靠。** 中间通知曾把“学习所需绑定证据不足”解释成“试点材料不足以支持上线”；最后完整分析到达后才正确承认原答复的问题。另一个新会话只查询 consent 状态后称“目前没有任何 Run 历史或样本”，与本环境已有两个正式 Run 不符；它没有实际查证跨会话历史。不能把这些模型表述当作运行状态事实。
3. **来源查找缺少顺畅的普通用户路径。** 请求先检查现成研究 Skill，模型虽然成功读取原生 Skill，随后却进行了五次 PowerShell 调用和一次文件查找。两次尝试使用保留变量 `$home`，日志明确返回 `Cannot overwrite variable HOME because it is read-only or constant`。错误后命令继续按真正的用户 HOME 读取其他应用目录；模型又误解释为目录映射。约 80 秒后通过“停止生成”中断，随后用普通对话要求只报告已加载的来源。没有下载、安装或修改 Skill；但无关目录只读扫描本身就是本次发现的范围控制问题。
4. **阶段 2 对照实验没有触发。** 两次正式研究摘要均为成功；普通任务失败反馈走的是显式反馈分析，而不是同一契约下两个失败加一个成功的重复 Outcome 入口。本轮没有 `request_tianwen_exploration`、实验臂、Candidate 评估或激活。不得据此判定实验实现成功或失败。
5. **阶段 3 的审核来源复用没有通过端到端验收。** 当前测试配置未设置 `learningSkillSources`，与默认不自动接纳外部 Skill 的边界一致。成功加载当前基础 Skill不等于发现并审核可供学习采用的来源；本轮没有 `inspect_tianwen_skills`、来源采用或新版本激活。没有为了覆盖分支临时编写、接纳一个“测试专用来源”。
