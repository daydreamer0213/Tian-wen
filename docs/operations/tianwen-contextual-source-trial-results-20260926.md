# 带原句语境的来源复核试验：旧必要条件仍误放行

R6-W3 的来源只说场地借用回复未到、周四约了电话、能否照常办尚未确定。它没有说必须等电话结束**才能**判断。新复核的解释把“待场地回复”与“周四有电话”拼成“电话是确定结果的严格前提”，正是原有双审核已发生的越界推断。即使给复核模型完整原句、原来源并明确提醒“时间先后不自动构成必要条件”，首次结果仍犯同一错误。因此本设计按预设停止；不能通过改提示词、重跑或更换标签把它改成通过。

隔离根目录 `D:/DevData/tianwen-contextual-source-trial-20260926`。冻结文件 SHA-256 `296e1fb0e78ed0d042fb99c23a358f841cbf35ce3130457697abd411345ca5b5`；宿主已退出，五次实际调用的结果文件时间窗合计约 93.4 秒。预先冻结的完整审计脚本在 T4 遇到“非支持状态却携带来源编号”时按规则失败，没有产生 `audit-final.json`，因而**没有整批审计通过或正式 cohort 裁决**。只读的事后关键题核验保留为 `evidence/critical-audit-posthoc.json`（SHA-256 `a39aa83db441c0ea34585946a510682c58679e59e3cbd4a059024220f87c2b98`）：它核对前三题的冻结材料、模型配置、原生会话与请求证明，验证三份关键结果确实来自真实首次调用；该事后核验不替代失败的整批审计。T4/T6 的原始输出不能被报作正式通过。

**裁决：停止把第三次语义模型复核当作来源正确性的补丁。** 当前缺口不是模型有没有看到关系或原句，而是它会把未给出的必要条件解释成严格蕴含。一个正常建议对照通过也不足以抵消这处漏判。下一阶段应重新限定哪些任务结果可以成为自动学习的合格来源，从来源明确、无新增必要条件的自然摘要任务切入，直接验收普通任务、真实反馈、研究决策、方法采用和后续任务效果的产品链路；对高歧义写作任务保留原答案服务，但不把本试验当作放宽其自动学习准入的证据。新的产品资格边界需要单独设计、工程回归与前瞻实测，main/Daily 继续 NO-GO。
