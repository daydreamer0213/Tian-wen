# 方法激活隔离：工程结果与发布边界

**结论：产品运行包现在会保留研究裁决，但暂停一切新的方法激活；main/Daily 继续 NO-GO。** 这是针对已观察到的语义漏判采取的隔离措施，不是证明模型审核已经可靠。设计和范围见[激活隔离设计](../superpowers/specs/2026-09-27-tianwen-guidance-activation-quarantine-design.md)。

E068 的普通任务把少量成功样本扩写为“链路已稳定”，两位审核者都判通过；旧 R9 还曾在候选答案有独立确认的事实错误时激活方法。后续完整语气范围诊断又误挡正常建议。现有 `accepted` 研究裁决不足以授权方法改变后续任务，因此先在方法生效边界隔离，而不修改历史研究、重跑旧样本或把诊断接入产品。

产品 bundle 将内部隔离标志同时传给演进账本和方法研究循环。新研究仍可记录 `accepted` / `rejected` / `inconclusive`；对于 `accepted`，循环不再追加 `guidance-activated`，重启后也不补做激活。账本自身拒绝新的直接激活写入，防止绕过循环。已存在的激活照旧回放；重复提交同一条历史激活仍可识别为重复，旧记录没有被回判或回滚。普通任务、反馈归因和研究试验的其他路径不受这个标志改变。下层未启用隔离的受控测试入口保持旧行为，不能视为发布许可。

验证先以失败测试确认旧代码允许直接写入和首次激活，再实现隔离。定向测试检查了产品显式／默认运行目录的两个隔离入口。脚本化原生研究到达 `accepted` 后没有激活记录，紧接着的普通任务仍采用父方法版本；重启后研究裁决仍在、方法仍未生效、没有追加激活，也没有额外模型调用。账本测试还确认被隔离的新写入被拒绝、历史激活可以回放。相关两组测试 **164/164**，运行包检查 **72/72**，全包 TypeScript 检查与差异格式检查通过。打包检查第一次运行时，类型检查生成的未打包文件覆盖了供测试读取的 bundle；重新生成正式 bundle 后，剩余三条断言显示旧白名单遗漏已存在的 `conversation-file-facts.js` 模块，核对来源后补入这一精确条目，运行包检查通过。正式构建脚本的 `pnpm run build:types` 在非交互环境触发 pnpm 的目录清理确认而退出；等价的声明生成和最后三个原生观察器打包步骤已直接执行并通过，未执行依赖重装或目录清理。

本轮没有真实模型调用，没有新的自然产品样本，也没有证明方法改善了后续任务。由于隔离，产品当前有意不能产出“新方法已激活”的正向证据；未来若开放激活，需要先设计独立的、绑定具体研究与候选的语义放行依据，再核对来源支持、当前版本和后续任务效果。不能拿本轮工程测试替代 E068/E069 未过的真实语义与完整学习链路门槛。

后续入口核对确认，正式 Web Profile 的运行插件名为 `@tianwen/runtime-bundle/runtime`，桌面宿主也以该 bundle 为运行包；这覆盖了隔离标志所在的产品入口。学习状态已分别展示历史 `accepted` 数量和当前实际生效的范围数，并明确说明前者不等于改进或激活。组合层回归首次运行有一条旧断言失败：它只允许三个学习工具，而既有文件任务设计早已在普通模型工具列表增加 `tianwen_captured_file_facts`。该工具对非授权的本地文件任务会拒绝执行。测试现明确允许并检查这一个受限工具，其他普通请求、回答、工具执行和权限事件仍逐项与未加载天问时相同；组合层与学习状态测试 **43/43** 通过。本次补核没有修改产品代码，也没有安装到 main/Daily。
