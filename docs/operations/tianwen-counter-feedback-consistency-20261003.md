## 缺陷与修复

研究正式打开时，原规则拒绝带有有效问题/偏好反馈的成功对照。但普通来源初筛可能把没有补充条件的偏好当作没有问题，新案例设计尝试也可能先接受这个对照。尝试按两个问题来源去重，因此研究随后被拒绝，却已经消耗了这对来源；干净对照后来出现仍不能继续。

首红使用原反馈修订/归因 API 的受控夹具，分别复现 checked 诊断误计成功候选和普通分支接受无效尝试；另一次首红明确普通 selector 会选中该对照。原 study-open 已拒绝它，故修复只是提前执行既有规则，不提高来源门槛。

Runtime 成功初筛复用原 latest/active/proof/非 positive 判定。Ledger 的新尝试/研究打开/激活写入入口提前拒绝原有效反馈冲突与原 native negative，拒绝不写记录、不消耗问题组合。普通 pending 规则未增加，checked pending 规则保持；最新有效 positive、撤回、无 proof、inconclusive 和 requirement-change 保持原含义。历史恢复和旧尝试去重不新增判断，不撤销或追认旧结果。
