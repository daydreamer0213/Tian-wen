# 文本研究新增独立结果核验接入

本轮补上一个核心能力缺口：现有独立结果检查只能检查代码写出的文件，文本和读文件回答的研究无法消费可信宿主核验。现在新增可选 `answerStudyResultCheck`，沿原五案例十臂研究接入事前固定的完整答案合同。仍保留两份模型评审、原研究裁决和启用守卫，没有默认检查器或默认授权。

这不是任意文本语义已经正确的证明，也没有新增自然任务、真实反馈、自然研究、真实方法采用或后续改善。完整目标 active/incomplete，main/Daily NO-GO，原门槛及十工作日窗口保持。

## 实现

- 新检查显式标记 `text-material.v1` 或 `file-chat-material.v1`。输入摘要绑定完整原案例材料：request/context 或 prompt、原要求/质量合同/已归因反馈标准。不能用空文件摘要替代。文件/chat 另外绑定原完整文件图；Ledger 的普通与 Native Goal 来源分支核对原输入。旧 code/files 行形状及摘要计算、无检查历史保持。
- 五项合同在方法提案前全部准备；任一缺完整独立依据就停止，没有模型兜底。同一闭包分别检查两臂；只传原材料和实际答案/只读文件图，不传方法、arm role 或模型裁决。材料与输出复制，答案作为数据而非宿主代码。
- 文本使用原 `recoverConversationTrial`，按原 worker 材料、模型、指导和输出摘要核原生答案；文件/chat 使用原文件收据。检查前后都核证明和当前授权/父版本。冷恢复仅核已保存结果和原证明，不重新 prepare/evaluate 或调用模型。
- 原独立结果采用条件保持：候选五项 verified、成功对照 baseline verified、存在原条件下的来源改善。不能拿只检查一条事实的弱合同冒充完整要求检查，也没有放宽普通任务资格或 checkedFailureSources。
