# 天问方法研究：独立语义审查工作单

**用途：**供独立审查者判断一项新研究的候选方法是否值得进入后续受控放行设计。填写本单不改变研究裁决、不解除方法激活隔离，也不证明未来任务已经改善。审查输入必须是[只读审查包](tianwen-guidance-review-packet-r9-diagnostic-20260927.md)所定义的完整材料，而不是十臂通过率或模型评审摘要。

只有**新研究 `accepted`、十臂和原生证据完整、尚未激活**时，才能填写下面的候选判断。历史已激活研究只能标 `diagnostic-historical`；`inconclusive`、缺失原始答案或证明漂移时，结论直接记为 `insufficient`，不能补写一个“通过”。审查前后记录审查包 SHA-256；字节变化即重新审查。

## 2. 核对来源与反馈原意

分别读取两条来源任务和成功对照的**原始请求、原回答和原任务双评审**。对有用户反馈的来源，把反馈原话、它准确指向的任务、原生归因结果、派生补充标准及研究实际看见的标准并排核对；对无反馈来源，核对原任务 `not-met` 的具体错误。逐条写下说话者、行动者、时间、否定、例外、已知与待确认的范围。派生标准若把“助手自己的建议”改成“用户自己的建议”这类主体变化，必须标为不忠实，不能因为原任务评审为 `met` 就略过。

## 3. 十条试验答案逐臂审查

五个冻结案例各审 baseline 和 candidate。先读原始任务与事实来源，再读**完整答案**，最后读模型的两份评审；模型的 `met` 只是待核意见。每条有问题的主张须引用答案中的准确位置、对应来源位置及理由。正常的可选建议不因未在来源中逐字出现就自动判错；但建议句里独立断言的外部状态、规定、批准或已发生行动仍要核对。

每个 candidate 至少单独检查：是否添加没有来源的必要条件；是否把已知状态扩大成待确认；是否把建议写成外部规定或已定决定；是否代用户、团队或发送者承诺未来动作；是否遗漏关键否定、时间、对象或适用范围。对每一项记录“无此问题／有，准确引文／证据不足”，不使用笼统的“看起来安全”。

## 4. 结论与停止条件

只允许 `clear`、`reject`、`insufficient` 三种审查结论。任何候选答案有明确无来源事实或反馈主体被改写，结论为 `reject`；材料、身份或来源不足以判断，结论为 `insufficient`；只有十臂均可逐项说明事实边界、来源标准忠实且没有上述错误，才可记 `clear`。`clear` **仍不是激活指令**：它只供以后设计与精确研究、候选版本、审查包摘要绑定的一次性许可；当前产品隔离保持开启。

## 历史负例检查：R9 只能记为诊断拒绝

R9 审查包状态为 `diagnostic-historical`，早已激活，不能拿本工作单补签。它的 source1/candidate 无依据地说培训时间须等周五后才基本落定；source2/candidate 把已知的日期和报名范围卷入“这些都等核对结果”，又新增最终通知承诺。source2 原反馈“你自己的建议”被派生为“用户自己的建议”，且旧研究当时没有看见这段原话。即使相关原生试验审核为 `met`，按本单的来源和逐臂规则也必须记为**诊断性 `reject`**。正常建议仍须按完整语气判断，不能把“建议先检查”本身当作无来源事实。原证据和限制见 [R9 导出结果](tianwen-guidance-review-packet-r9-diagnostic-20260927.md)与[事实／建议失败诊断](tianwen-claim-mode-boundary-diagnostic-20260927.md)。
