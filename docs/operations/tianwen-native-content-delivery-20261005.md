## 产品实现：标清终答，同时保留全过程事实审计

核对源码发现原内容评审把全部 append assistant 回复视作答案，文件捕获也拼接全部回复。它没有标明哪个是用户实际收到的最终交付，与已有独立答案检查的 SDK 终答选择不同。历史 DEV 的双评审漏判确实存在，但未证明这个边界是当时漏判的原因，不重评或改写旧材料。

新 Task 在首次模型请求前冻结可选 `deliveryPolicy:native-terminal.v1`，材料标记原 preparation 之后最后一条非空 append assistant 消息的 ID/seq。内容评审的格式和唯一交付要求针对该终答；全部中间回复仍作为 answer 单元接受事实审计，不提升为事实来源。文件输出仍照原文件捕获和执行证据审查。文件 capture.answer 取终答，并在材料和证据投影两层核验一致。终答错误、空白或仅工具块不得用早答顶替；SDK 空 content 数组保持原跳过语义。
