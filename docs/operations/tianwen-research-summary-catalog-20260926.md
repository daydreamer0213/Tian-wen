# 普通摘要误选研究技能：目录描述收窄

状态：029 真实结果后的开发分支工程候选，尚未用新真实模型任务验证。029 的原始 `not-met` 和完整连接 NO-GO 不改判。

029 的普通两句摘要任务没有 `<research_packet>`，也没有研究包提交工具；模型仍调用 `research-summary` 技能，搜索包文件，最后向用户解释技能不可用，把本该只有两句的答案变长。原生会话显示 DSH 的技能清单只把 `description` 显示给模型，`whenToUse` 的明确包条件没有出现在该清单里。旧描述只说“Summarize a bounded research packet”，模型把普通给定材料摘要也当成匹配任务。准入与两份复核均按原样保存，复核正确识别了输出限制违反。

仅把基础技能在目录里的描述改为：只有直接提供 `<research_packet>` 且含已标识发现与不确定项时才适用；普通摘要不使用此技能。技能正文、提交工具、准入判据、学习门槛和任务复核均未改。这样模型在决定是否加载技能之前，就能看到原本只写在 `whenToUse` 中的关键条件。它降低误选机会，**不能保证模型在所有自然语言请求中都正确选择技能或严格按格式回答**。

基础技能描述属于其版本身份，变更后新任务会用新身份；已有任务和已保存的方法指针仍按冻结的历史内容恢复，不能把旧记录改写成新版本。相关研究技能、原生准入、版本回滚、显式纠错和探索测试共 133 项通过，八包 TypeScript 类型构建通过。首次扩大测试时有 21 项因为缺少 `TIANWEN_DSH_PROBE_ROOT` 测试目录而未执行，设为 `D:/DevData/tianwen-dsh-probe-029` 后 53/53 通过；这不是产品代码失败。
