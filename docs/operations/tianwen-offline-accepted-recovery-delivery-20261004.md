# 重启后自动完成已裁决方法的启用

本轮修复了自动学习核心中的一个真实缺口：研究已经保存“接受”决定，但方法启用记录尚未写入时，如果进程退出，重启后可能一直停在那里。现在可以凭原来保存的完整证明继续启用，无须新开对话、重新调用模型或让用户再次确认。

这是工程恢复能力的交付。完整自动学习目标继续 active/incomplete，main/Daily 保持 NO-GO；本轮没有新增自然任务、真实反馈、自然研究、真实方法采用或后续任务效果。

## 原因和实现

原服务会识别已接受、尚未启用的研究，但启动时只调度仍在运行的普通根 Agent。冷启动没有这类 Agent 就不会恢复。持久化唤醒又先选择新研究来源：已研究过的旧来源不能再次被选中，导致直接返回，原恢复无法到达。

修复复用原服务的持久化唤醒：启动时唤醒这类普通研究的原来源，先恢复原接受决定，再选择新研究。同一作用域的持久化队列与对话队列共同等待一个恢复 Promise，避免恢复尚未完成时选择新研究；服务关闭后不再开始延迟恢复，排空也跟踪它。原 Goal 唤醒、授权、证明、结果检查、父版本及隔离规则保持。

前一轮提出的反馈恢复疑点经原代码核对已排除：正常 scanSession 已取消未完成评估，不能只凭同 ID 早返回声称永久等待。本轮没有另造反馈恢复机制。
