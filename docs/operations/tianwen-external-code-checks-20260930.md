## 当前交付

## 时序与身份

观察器持有一个轻量检查成员，复用既有 Agent、Session、文件恢复与唯一 Evolution 账本，没有新增 Service、Profile、注册表或第二个 Agent 循环。

原生 `agent/request` waterfall 先取得公开接口返回的实际 `LlmCallConfig`；在首次 `llm/stream` 和模型观察之前，宿主 prepare 收到精确原请求/上下文/当前 task、模型摘要和 cwd。它须自行判断该原请求是否适用，返回 undefined 时原任务继续。

准备记录 `task-external-check-prepared` 绑定 taskId、preparedSeq、原请求/上下文/准入/实际模型摘要、checker 身份和合同摘要、冻结目标文件输入摘要。已有模型观察、文件调用或完成结果就不能再准备；原生状态在准备期间变化亦不登记。检查实现由宿主程序提供，模型没有修改检查器或提供预期值的工具入口。**元数据声明本身不证明独立或完整正确**。

完成后先确认原生会话保存成功，再复用已有 exact native span、请求/上下文、文件调用/结果及模型配置恢复；核对冻结输入、模型与前置时序后调用已保存闭包一次，再确认保存成功并核对原生证据，最后写 `task-external-check-finished`。结果绑定 prepared 记录摘要、完成摘要和文件结果摘要，只表达该项检查的 `verified/rejected/unverifiable` 及<=4096字节说明。

两个记录都严格解析、不可改写、重复幂等，写入和冷重放共用同一检查，要求记录发生时对应 revision 的 v3 同意。后来撤回不使此前合法记录失效，撤回后的新分析记录不能通过重放绕过。目标文件仍用8文件/96KiB单文件/128KiB总量；仅保存摘要，不复制全量编译依赖读取闭包。具体可信检查实现应只消费冻结材料，不执行生成代码或从当前磁盘补来源。

## 失败与重启

- prepare 不适用或抛错时，普通任务照常执行，不把不适用算失败任务。
- 缺文件证据、输入变化、模型变化、原生记录变动或检查抛错/返回非法结果时，只记 unverifiable，缺证时不调用检查器。
- 已持久准备但在重启时丢失闭包的任务，只写“无法核验”，不在答案后 prepare，不重跑检查；已有结果原样重放。
- 撤回同意会释放等待并清除闭包，迟到回调结果不写入。同步执行的宿主代码不能被 JavaScript 的取消信号强行抢占；此接口要求可信实现尊重取消并保持冻结材料边界，不能当任意脚本执行平台。
- external 模型 met 仍 inconclusive；检查结果不替代模型 review，不进入研究来源/accepted/激活许可，原话与历史责任保持。
