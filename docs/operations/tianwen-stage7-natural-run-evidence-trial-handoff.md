# Tianwen Stage 7 natural DSH Run evidence handoff

DSH `0.1.0-rc.7` remains the only product Agent Runtime. Stage 7 adds a
pre-Turn, manifest-bound natural Run evidence intake path to that Runtime; it
does not add another Agent loop, Provider wrapper, ledger, store, or scheduler.

The zero-cost fixture proves only the mechanism, pre-Turn ordering,
provenance, and `met/no-case`: a normal DSH Goal/Session, parent Skill
manifest, final verifier Evidence, Outcome intake, recorded Skill-use, and
governance non-interference. Its scripted adapter is not a configured-Provider
natural receipt and is not an efficacy claim. No configured-Provider natural
receipt is claimed until one actually runs once through the normal configured
DSH path.

The fixture does not manufacture a Ticket, Case, Candidate, live B/C
Evaluation, Shadow, Active Pointer, Promotion, Reject, or rollback. Exact CNY
billing is unavailable and non-bearing. It adds no price polling, price
snapshot, budget store, reservation, or request gate.

The demo has 0 Provider network requests, 0 paid tokens, 0 exact CNY, 0
Docker, 0 external database, and 0 user data. It does not use Python Alpha,
RepoTaskRuntime, AlphaRuntime, Artifact, Dynamic Cordis, or the global Champion
for activation, routing, or state change.

The managed product root has since migrated successfully from the supported
DSH rc.6 predecessor to rc.7. Session and Evolution data were byte-identical
before and after that installer transaction.

One configured natural invocation was then attempted once. It stopped before
its first Turn, with zero Provider requests and zero tokens. The observed cause
was that inherited DSH terminal output shared the same channel as the child
safe JSON receipt, so the parent could not promise a parseable or safe receipt.
No Ticket, Candidate, Evaluation, Shadow, or Promotion was manufactured.

The correction pipes the natural-trial child's output, validates one bounded
receipt, and re-emits only a normalized safe receipt. Invalid or mixed child
output becomes a fixed safe failure without forwarding raw terminal bytes.
This is an execution-surface correction only; it does not change DSH's Agent
loop, Provider, learning path, or governance decisions.

A configured-Provider natural receipt is still not claimed. Only after the
correction reaches exact-main CI and is installed into the managed product root
may the already authorized single natural invocation be retried. Any real
result remains limited to the natural producer-to-consumer chain, not
production-user distribution or general efficacy.
