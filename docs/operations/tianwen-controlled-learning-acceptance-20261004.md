# 主动设计问题与后续任务：受控完整学习验收

## 最新所有者要求与纠偏

所有者随后确认：这一思路适用于项目其他部分开发；还缺什么条件，可以主动模拟触发，只要实际有效，不要过度限制导致项目阻塞。将其作为项目执行原则：先构造最短而有意义的环境和输入，事前写清要观察的效果，再实际运行；结果满足这一阶段要求就收口，不事后追加自然等待/更多样本/更多外围检查。只有某项模拟不能回答当前问题时，指出具体差别并选择另一种有效验证，由执行者解决，不笼统要求所有者准备条件。形式合规和检查数量本身不是效果。

2026-10-04所有者明确指出：可以主动设计失败、问题环境和模拟后续任务，观察项目是否改善；不能为了等待自然积累的相容问题而反复拖延开发。此要求优先于旧交接中的“不能刻意制造失败”和“必须等待自然问题”解释。目标继续active，不回推问题准备责任给所有者。

此前正确边界是“不把模拟证据冒充自然使用证据”，不应扩大为“不能设计模拟实验”。主动构造的失败和未来任务可以承担完整链路的工程验收；故障注入、脚本控制、真实模型行为和实际检查结果分别注明。既有自然历史不改写，已结束的旧练习不重投。原main/Daily当前NO-GO及治理/权限/同意/独立复核/语义守卫不因模拟自动解除；它们也不能成为停止DEV实验的借口。不把后续自然积累设为本阶段完成的必要条件。

## 可直接推进的一批实验

沿已交付原Goal与可信答案生产者，使用新专用DEV范围及同一冻结执行版本，不另建Agent/循环/平台。执行者自行准备完整原始记录、任务、结果规则与环境，不索题或催评OfferGo。

1. **主动建立问题环境**：两个相互独立、会暴露同一机制问题的任务和一个正常对照。允许明确标记的故障注入，保留发生位置、原配置、原结果和完整原生事件；问题来源记为受控，不能记成未受干预的模型错误。不要伪造用户看稿反馈、修改完成记录或把检查基础设施损坏当任务做错。
2. **原机制自动处理**：按现有准入、同意、归因/来源选择、五案例十臂、双评审和独立结果检查开展研究。执行者不手写研究结论、方法启用记录或用默认隔离开关冒充错误方法被检查器挡住。五份独立依据按原时序固定，不由候选答案反推。
3. **主动建立未知后续任务**：事前固定四项新任务（两个目标问题任务、一个邻近任务、一个正常对照）及完整原始判断依据，使用新数据/边界而非旧题换名。候选方法提出和启用前完成冻结，任务与正确结果不泄露给研究者。任务可以模拟，不必等待真实使用事件出现。
4. **观察真正作用**：在同一模型、执行环境、权限与故障条件下，分别使用原基线和被原治理机制启用的方法。只有方法变化，不能在启用同时偷偷修环境、改变规则或按“是否带方法”直接写定正确答案。保存真实输出、独立结果和方法绑定，比较目标任务改善与正常任务退化，检查撤回后原基线恢复。若使用脚本模型，只能说明机制；方法对真实模型的效果另用真实模型运行记录判断。

故障注入可以保证检验“遇到问题是否处理”的分支；它不能保证候选方法有效。方法没有改善或导致退化时，原机制应拒绝/撤回，这是可报告的验收结果；执行者负责定位具体原因并实施下一项修复，不能再次笼统标整个项目blocked或要求所有者造题。

## 本阶段结果如何使用

受控完整链路的完成信号是：问题确实被原机制接收，研究与独立判断真实运行，方法按原治理启用/拒绝，未知后续任务能够比较效果，错误或退化能被阻止/撤回。不得只用mock替代全部执行，然后宣布真实模型改善。

本阶段不再以自然重复问题积累作为先决条件；仍如实区分“受控环境完成了自动学习与后续验证”和“日常使用普遍变好”。既有研究格式、语义与发布约束不追加、不续期。不能用没有自然样本将已经通过的受控功能验收重新判成没做过，或使阶段永远无法收口。
