> 状态：2026-08-24 架构监督冻结。本文只处理 activity-01 的操作合同错误；它不修改产品能力。

## 1. 结论

activity-01 已正式消费并停止，但没有运行模型或 lifecycle。唯一首因是原 canonical 9B.2 把
public CLI 写成了位置参数简写，遗漏 `--model`。official launcher 和 `main()` 已进入，随后 usage
parser 以 exit 2 拒绝；selection 没有改变，Session/Evolution 为空，最终 official status 仍为
offline 且 `modelRequestsDelta=0`。

这不是 Tianwen、DSH、DeepSeek、installer 或 Provider 缺陷，也不允许把 activity-01 改写成
“未尝试”后补跑。恢复方案是一个新的 reviewed operation-authority SHA、对应 exact-main CI 和
全新隔离的 activity-02。产品代码、Profile patch、CLI parser、依赖和生命周期机制保持不变。

## 2. 为什么必须是 activity-02

原计划 9B.4 在运行前已经规定：任何 official nonzero exit 都是 activity-01 的正式结果，失败后
不 rerun、不补阶段、不继续 partial activity。零 Provider、零 Session 只说明失败发生得早，不撤销
这条证据合同。

前一轮 outer shell 的 command-not-recognized 不同：那次 official launcher 根本没有进入，因此只是
pre-invocation harness failure。activity-01 的 usage exit 2 已越过这条边界。两份证据必须分别保留。

## 3. 采用现有公开接口

正确语法早已由 `packages/tianwen-runtime-bundle/src/cli.ts`、model configuration 设计与公开测试共同
固定：

```text
tianwen model use --model deepseek-v4-pro --data-dir ABSOLUTE_PRODUCT_ROOT --json
tianwen model status --data-dir ABSOLUTE_PRODUCT_ROOT --json
tianwen controlled-lifecycle --manifest ABSOLUTE_MANIFEST --data-dir ABSOLUTE_PRODUCT_ROOT --json
tianwen model use --model offline --data-dir ABSOLUTE_PRODUCT_ROOT --json
tianwen model status --data-dir ABSOLUTE_PRODUCT_ROOT --json
```

执行时继续使用 official receipt 中的 `.CMD` launcher、PowerShell call operator 和逐 token argv 数组；
stdout/stderr 分开保存，调用后立即保存 `$LASTEXITCODE`。不再经过 `cmd /c` 字符串、嵌套 shell、
`Invoke-Expression` 或位置参数简写。

这属于复用现成接口，不建设 launcher helper、参数 DSL、retry policy 或 dry-run。

## 7. 唯一正式顺序

```text
model use --model deepseek-v4-pro --data-dir ABSOLUTE_PRODUCT_ROOT --json（0 request）
→ model status --data-dir ABSOLUTE_PRODUCT_ROOT --json（0 request）
→ controlled-lifecycle --manifest ABSOLUTE_MANIFEST --data-dir ABSOLUTE_PRODUCT_ROOT --json（只运行一次）
→ 保存唯一 safe receipt/exit
→ model use --model offline --data-dir ABSOLUTE_PRODUCT_ROOT --json（0 request 安全收尾）
```

前两步任一 official nonzero/无合法 receipt 就不运行 lifecycle；但 activity-02 已消费。lifecycle 一旦
调用，无论 passed、stopped 或 transport failure 都是唯一结果。所有分支都只做一次 offline 恢复和
最终 status；恢复失败也不重跑。

## 8. 证据分级

- `receipt-certified`：只来自合法 official product receipt；
- `durable-observed`：只可来自成功完成的独立 Session persistence 归约；本 activity 的两个 failed
  checker 都没有产生这一级证据；
- `filesystem-observed`：外层只读快照对 root/entry/digest 的有限观察，不升级为 Session 或 Provider 事实；
- `unknown`：没有合法 receipt 或独立事实源的 Provider 账户请求、tool body 执行和内部阶段。

usage stderr、raw error、既有用户路径、凭据值、prompt/output、工具参数/结果、evaluator reasoning、
Skill 正文和实际运行产生的 Session/Run/Candidate ID 不进入 README、operations handoff 或安全回执。
本 canonical packet 为了执行隔离而列出的固定 D: root 和合成 Session allocation 不是用户产品数据，
但也不复制到最终公开摘要。activity-01 的零值不能混入 activity-02 的结果。
