# 固定 DEV 宿主研究结果接入

当前源码 b79dc1760e072bd546f9ab8236bdf63f51f906a8 的公开发行根已有普通、单研究、五角色 Node 工厂；`scripts/development-isolated-node-check.mjs` 只消费普通工厂。研究调用者仍需自行传执行配置，未共享当前固定 JS/TS 宿主。上一轮实际任务功能失败已保存，正式档案15观察/14识别完成/0研究，不用本接入改变历史或凑来源。

采用原薄入口扩展，复用发行清单的实际 `.default` 根导出。增加 `createDevelopmentStudyIsolatedNodeCheck` 与 `createDevelopmentStudyIsolatedNodeCohortCheck`，分别转发原工厂。拒绝调用者顶层和每角色的 `isolated` 覆盖；普通/单研究按目标路径选固定JS/TS配置，五角色按各自完整保存材料的唯一outputPath选配置，支持同组JS/TS任务。只补配置，原请求、条件、质量、案例、顺序及模型摘要保持。

不另建研究循环、自动任务发生器或来源注册表；原loop消费 `studyResultCheck`，仍只在原合法来源组成立后准备五项检查，原材料漂移停止。固定宿主JSON、实际Runtime运行字节、身份算法、正式隔离/同意/NO-GO及十工作日窗口不变。无需为了本接入制造两条失败；合法来源缺失不禁止完成这项工程。

考虑过两种替代：继续每调用者配置容易漂移身份；将开发机路径写进Runtime会污染产品配置。故选择现有DEV薄适配，原普通API仍使用完全相同的配置。

验证范围：先见新导出缺失首红；默认Node测试实际发行根装配、闭五角色、材料/模型/顺序漂移拒绝、覆写拒绝及克隆隔离。新实际Docker控制只核对本宿主五角色准备、JS/TS各一次运行、条件及身份，避免重跑已完成全研究生命周期。实际发行runtime子入口消费这两个producer，原服务及配置登记、无合格来源时零研究/零模型；明确不把装配当自然研究。本轮保留小回执与原账本完整字节，唯一自有容器清理、历史84ID保持、Docker恢复停止、D≥15GiB，不复制环境/依赖。
