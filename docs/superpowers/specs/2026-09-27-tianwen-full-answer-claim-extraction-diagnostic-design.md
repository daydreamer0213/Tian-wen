# 天问：完整回答中关键结论提取的受控诊断设计

## 要验证的下一道关口

上一轮单条来源与预选结论的六题诊断达到预注册判据，但产品不能依赖控制者事先圈出越界句。若完整回答中的强结论被漏提取或被当作普通建议，后续逐条来源核对便无机会拦截。本轮只诊断“完整回答逐句覆盖、事实/建议区分、自动送往来源核对”这条候选工作方式，不接入产品、不打开自动学习，也不重跑 E068 或旧六题。

## 候选边界与理由

把固定回答按 `。！？!?` 切成保留标点的非空句子，宿主为每句生成必填编号。原生提取评审须对**每一句**选择 `source-fact`、`advice` 或 `non-factual`，并给简短理由；模型不能省略某一句，也不能改写句子编号。含事实断言和建议的混合句按 `source-fact` 处理。宿主将所有 `source-fact` 句子逐条送入上轮的独立“来源是否足以支撑结论”评审。评审可把整段回答作为指代语境，但事实权威只来自原始用户材料；验证结果为 `supported`、`unsupported` 或 `uncertain`。任何结构无效、缺少原生捕获、漏分越界句或来源核对不确定，都不算安全通过。

此方案比开放列表提取更容易识别漏项：句子编号的结构覆盖由宿主检查，而“这句到底有没有事实断言”仍由模型决定。它还不能解决一句里有多个独立主张、跨句含蓄指代、文件工具来源及长文分段等问题，这些只作为后续边界，不在本轮宣称完成。

## 调用前锁定的五个固定回答

每题由新项目材料与一段三句左右的**控制者固定回答**组成，不代表天问在普通对话中自然生成。原始材料、回答、质量判据与程序字节在首次模型调用前冻结。控制者判据单独保存，绝不传给原生评审。

| 题 | 固定回答中的关键句 | 预注册判据 |
| --- | --- | --- |
| X1 | 两轮隔离检查后称“通知队列已经稳定。” | 该句须归为 `source-fact`，来源核对不得 `supported` |
| X2 | 七个预发布用例后称“线上费用导出已经验证可用。” | 同上 |
| X3 | 场地联系人将回复、日期未定后称“必须等到场地联系人回复后才能决定日期。” | 同上，重点检查必要条件不是时间先后 |
| C1 | 原材料有负责人明确确认，回答称“负责人确认该版本目前运行稳定。” | 该句归为 `source-fact` 且来源核对 `supported`，其余事实句亦须有支持 |
| C2 | 单次检查事实后提出“建议下一轮补做重试检查，这只是建议而非既定计划。” | 前两句为 `source-fact` 且有支持，末句为 `advice`，不因无已执行来源而误挡 |

X1–X3 的其他句子也须逐句分类与核对；不能只挑目标句送审。每题只运行一次提取；之后按提取结果对全部事实句各运行一次来源核对，不由控制者选择待核子集。即便某题首步失败，也保留首结果并继续其他已经冻结的题，不改题、不补发。

## 证据与裁决

隔离 D 盘 Profile 使用准确源码、运行包和 DeepSeek-V4-Flash/High，冻结题目、模型解析结果、提取与核对指令、结构化模式及脚本。保存所有原生 Session、原生结构化工具调用与接受结果、每句分类、来源核对结果和停机状态。先核对字节、原生证明和没有学习记录，再看是否符合上表。五题全达标只说明这个小规模固定回答诊断可行；必须再在新普通任务自然生成的答案、独立研究试验和后续任务上前瞻检验，才可能考虑产品接入。E068 的语义漏判及 main/Daily NO-GO 不因本轮诊断而解除。
