# E040 后续：让大文件审核引用保持有界

## 问题与边界

E040 的真实桌面任务证明 68,047 字节文件能够进入审核材料，但第一审核子会话把带前缀的引用交给 `structured_output`。原生参数模式枚举了所有原文片段，参数错误回执携带整个列表，随后子会话超过模型上下文上限。产品保持了 `inconclusive`、空证明和零研究，未误判成功。

目标是让原生工具参数不随原文长度线性增长，同时保持每条审核引用只能来自实际冻结来源或答案。无效引用必须在形成审核结论前失败关闭。此次不改变文件容量、审核结论规则、模型配置、研究门槛或 E040 的历史结果。

## 方案

曾考虑把引用替换成短 ID 并在宿主映射回原文，或仅在证据超过阈值时禁用枚举。短 ID 会改动审核材料和持久证明的含义；分段策略则保留两套校验路径。采用较小的变更：原生模式仅要求引用为字符串，不携带原文枚举；若没有非空原文，仍只接受空引用列表。材料字节上限继续在宿主检查。

审核子会话返回后，宿主在把结果放进双审核列表前，逐条核对引用是否为非空字符串、且完整出现在同一个 `claimEvidence.items[].text` 中。该规则与既有冷恢复校验一致；普通审核路径也已有来源校验。无效引用抛出 `invalid-judgment`，不启动第二审核，也不产生成功学习记录。引用数量和长度仍由既有审核记录解析器限制。

## 验证

先用测试复现旧行为：长原文让原生模式膨胀，带标签的无效引用不能在首个主张审核后干净结束。修复后确认工具模式大小有界、无效引用被实时拒绝、有效双审核和冷恢复仍通过。再运行相关集成测试、全包类型检查与差异检查。工程通过只表示准备好冻结下一候选；真实 DeepSeek 桌面任务需要在新隔离配置档中重新验收，E040 不追认通过。
