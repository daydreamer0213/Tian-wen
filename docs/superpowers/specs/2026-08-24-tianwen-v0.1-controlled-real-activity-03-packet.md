## 9. Evidence and stopping boundary

Formal success and failure follow the approved Activity-03 design. Evidence is classified only as
`receipt-certified`, `durable-observed`, `filesystem-observed` or `unknown`. Session events do not
prove Provider-account requests or actual tool-body executions. Public summaries and safe
attestations exclude raw prompts, model output, tool arguments/results, evaluator reasoning, Skill
content, runtime Session/Run/Candidate IDs, paths, credential values and raw errors.

Any readiness failure preserves the fresh scene and stops before formal model use. After formal model
use begins, the first nonzero, invalid receipt or transport failure consumes Activity-03 and is not
retried. The single lifecycle result is permanent: no task, arm or Session is supplemented, no result
is selected away, and no Activity-04 is created automatically.
