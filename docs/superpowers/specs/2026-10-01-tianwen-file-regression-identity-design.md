## 实际问题与授权

所有者授权自主选择可推进天问开发的任务，不等待 OfferGo 新稿评价。dcfc0bc 下，普通文件任务的来源选择已区分文件输入，`rollbackIfNeeded` 与账本 regression 校验却仅按 requestDigest 去重。同一请求处理不同文件内容的两次后续失败会被合并，不能触发原有的两次不同任务回滚。这是既有文件学习能力的治理缺口，不是新的学习放行条件。

## 选择与实现

仅改提示词无法修正运行时计数；直接改所有历史 regression 的含义会破坏旧证据。选择在现有回滚记录上为新文件 regression 增加可选 `evidenceInputPolicy: captured-files.v1`，明确冻结其检查语义。旧记录无字段按原 requestDigest 规则重放，重复写仍幂等；新的文件 regression 必须带此字段。文本和其他回滚原因不允许此字段。

一个共享纯函数从真实任务记录计算文件输入摘要：原 requestDigest 与捕获的 path/content 前像。路径按既有大小写别名规则转小写并排序，不让读取顺序或大小写制造不同输入；null 与空串仍不同。必须 local-files、completed、有完整非空输入和匹配的 files 结果、无 fileUnavailable，且结果 inputsDigest 与原捕获顺序摘要一致。输出正文、候选文件内容、工具/会话标识、输出路径排序不参与输入身份，不读取当前磁盘文件。

运行时按这个摘要过滤不完整证据、去重，保留至少两条不同失败条件，写带政策的记录。账本对带政策的记录独立核对准确模式及摘要，不信任运行时声明。现有其他资格、实际 not-met 判定、版本/模型/族/时间/作用域校验不改。没有配置新检查、执行候选、启动模型或解除激活隔离。

## 正常、反例与失败

- 同一句请求，两个不同前像，准确方法版本下的两次完整失败：新记录可回滚且冷恢复一致。
- 同一句请求及同一前像，只有读取顺序/路径大小写/答案变化：不能累计两次；一个不同失败也不能回滚。
- 缺失/冲突前像或不可用文件证据：不计为新文件 regression；其他合法失效原因仍可回滚。
- 旧合法无政策记录仍按原请求去重重放，字节不迁移；重复写不要求补政策。
