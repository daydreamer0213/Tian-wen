# 新建目标的不存在读取：完整证据链窄修

实际9148任务在read新目标时返回FsError/FS_NOT_FOUND，观察器统一isError中断；即使略过该中断，ancillary冻结及冷恢复仍要求每个read成功。修复必须同时覆盖实时捕获、唯一原生结果身份、末端冻结和冷恢复，不能只改一行或把错误结果变成成功。

允许的唯一例外：files输出任务，初始完整捕获是null，原生根read返回准确FsError/FS_NOT_FOUND；同一路径在该失败结果之后由成功write创建，之前没有成功写/改，终态内容非null且路径属于本任务输出。原始read仍是failure动作；不改tool结果、旧账本、原review或任务资格。缺失参考未创建、chat、其他错误、已有文件、未完整创建、错误/重复/错序native result、越界/取消/撤权继续停止。

比较方案：统一忽略FS_NOT_FOUND会误放行缺失参考；仅观察器延后不足以通过原生冻结/冷恢复；采用同一纯谓词验证完整创建顺序，观察器只暂存明确缺失read并在终态复核。复用现有文件输入和native结果，不加新持久格式/发布门槛、不修旧任务。

最小红测试先用实际native read→write→read复现，再覆盖写其他目标、无创建、普通read错误/已有文件、并发读取、冷恢复与native结果篡改。原缺失chat/取消/撤权等回归保持；类型/bundle和修改完整TS检查、独立审查后提交。另只读调查上轮工具限制中出现edit的宿主原因，未经证据不归为模型违规。生成物仅D小日志，D≥15GiB；原隔离/NO-GO/十日窗口保持，完整学习仍active/incomplete。
