每条命令都使用 install receipt `binDir` 下 canonical real official `.CMD`、PowerShell call operator、

序列，并只进入 offline 安全收尾。

## 6. 一次性 generator 与 checker

generator 必须：

1. 确认 operation root 不存在并以 exclusive create 物化；
2. 从本 packet 指向的 reviewed task authority 读取固定任务事实；
3. 生成 20 个新 workspace、manifest 与本 packet 的 25 个 Session allocation；
4. 用 production parser 重读 manifest，并逐字重读 20 个 `case.md`；
5. 计算 generator、checker、manifest file/semantic 和 workspace-set digest；
6. 写入 freeze receipt；不创建 Agent、Session、Evolution、model selection、Provider、Goal 或产品状态；
7. 任一步失败即保留现场并停止，不覆盖目录重试。

原 checker 与 Task 4C recovery checker 的唯一 readiness 调用都已永久失败并保留：它们没有认证
0/0/0/0/0，也不得重跑、覆盖或再用于 postmortem。它们的 failure transport 只证明外部 evidence tool
未完成 inspection，不证明产品状态不干净，也不改变本 packet 的 task、workspace、Session、manifest 或
freeze identity。

最新 Task 4D authority 不再增加 checker 或独立 readiness 调用。第 5 节唯一一次 official
`controlled-lifecycle` 的 product-native preflight 必须在首个 Agent/Provider/model/tool body 前用
production parser、installed loader/Evolution/Session persistence、20 workspace、credential、selection、
normal/0 retry、tool surface 与 parent Skill identity 完成准入；child gate 失败返回有限 stopped receipt，
更早的 parent/transport failure 可以没有 lifecycle receipt，但两者都在 Provider 前停止并成为
activity-02 正式结果，只做 offline 收尾。该门提供“脏状态不能进入真实运行”的安全性，但不生成独立
readiness attestation；两次 failed checker 也不得被改写成 `durable-observed` 零值。
