# 原生Goal任务退化进入既有回滚

继续已授权三项收口计划第三项，不新增交付阶段、样本数量或发布门槛。基线2e5c4c2。现有原GuidanceLoop和Ledger的regression分支只消费ConversationTask，native来源事件虽然唤醒原owner，却不会被回滚计入。

采用明确native证据策略，复用原rollback记录、版本链和原两项独立退化条件。普通记录及历史语义不变；不伪造ConversationTask，不建立新回滚服务。回滚证据保存原sourceId和冻结source记录摘要，核原scope/方法版本/模型/质量合同/族/输出模式/同意及原结果。必须是实际启用之后的原结果；晚发布旧结果不能算后续失败。两项实际输入不同，原语义问题或限定code/files原明确条件失败才计入。程序条件失败另核原功能输入摘要与冻结内容文件一致，复用已有研究条件。取消、仅基础设施不可核验、没有明确语义问题的inconclusive、成功、不同版本/模型/范围不计入；已completed且原语义not-met即使功能检查器不可用，仍沿既有语义问题分支，不能混同基础设施与内容结果。

未来原finish来源额外冻结原要求与规范化文件的输入身份，防止读取顺序/路径大小写/输出路径顺序制造不同输入；旧缺字段来源原样恢复，不补造身份。原material/inputDigest继续保留精确材料绑定，规范化身份仅用于前瞻去重。原Loop可同步验证已绑定Ledger来源，关闭/支持撤回继续沿原规则；纯Ledger是最终写入校验边界，冷重放不得新执行或追加回滚。

受控开发账本可验证原共享接受裁决后的明确启用、后续原Goal结果及退回旧版本，不能把控制启用叫自然收益。main/Daily的激活隔离及原发布规则不改。开发真实启用和未来自然效果仍在同一第三项后续推进。

实际文件来源验证另复现原Goal的chat/v2动作投影被共用内容证据拒绝。仅明确native-goal-task/chat/v2时核全部原文件不变且无write/edit，保留原call/result/status；普通v2/chat及其他旧协议边界保持，不制造v1只读证明。这是原未来来源连接的必要修复，不增加验收。

未选择单纯按not-met标签回滚，因为它丢失原来源/方法/输入/模型绑定；未选择新回滚服务，因为它复制原owner和版本链。自动授权已由用户持续推进指令提供，不再次索题或批准。
