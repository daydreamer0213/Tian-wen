# Tianwen v0.1 真实受控 Skill 生命周期操作设计

> 状态：2026-08-23 架构监督冻结，并在 Task 9B.0 首次官方安装取证后完成 readiness 更正。
> 本文只服务 v0.1 的一次 development-only 真实 Provider 生命周期，不把测试场景包装成
> 自然用户或外部用户证据。

## 1. 结论

当前 `main@95077be9265818cbcec443a89a71e22363ae1cde` 已经具备 B/C、盲评、
隔离 Shadow、Promotion、Rollback 和 Restore 的产品机制。exact-main CI run
`32641914572`、event=`push`、attempt 1 的 Python、TypeScript、installer-windows 三个 job
全绿。

Task 9B.0 的唯一一次官方安装已经成功：ready receipt 与 archive digest 闭合，18/18
Runtime Bundle publication 均为独立 regular file，Sessions/Evolution 仍 fresh。随后唯一一次
official `tianwen.CMD model status --json` 虽 exit 0，却产生 0-byte stdout。这个失败没有重跑。

只读根因不是 JSON 格式或 installer 内容不一致，而是已安装 CLI 的 main-entry 判断比较了两种
合法但不同的路径拼写：Windows `.CMD` 传入顶层 pnpm link 路径，`import.meta.url` 使用 canonical
real path，现有 lexical equality 因而把真正的 CLI 当作“被 import 的库”，静默不调用
`main()`。现有测试直接执行 receipt 中的 real JS 路径，绕过了普通用户实际使用的 launcher。
因此它是正常 installed CLI 的核心可达缺陷，必须先闭合。

另外，正式 controlled 命令目前仍会继承 DSH DeepSeek 默认 `maxRetries=2`，并启用首次 prompt
的模型标题 provider。前者与冻结的单次尝试冲突，后者可能在 25 个 fresh Session 上产生额外、
未受本活动归约的 Provider 请求。DSH rc.7 已提供标准 patch seam；无需 Tianwen 自建重试器、
标题服务、预算器或遥测。

本阶段新增一个最薄 one-shot（一次运行后退出）入口：

```text
installed tianwen CLI
→ installed DSH rc.7 Profile
→ one-shot controlled operation runner
→ 现有 TianwenLearningIntake / TianwenEvolution / TianwenSkillEvaluationService
```

它只负责验证冻结任务包、注册一个隔离 B Skill 和两个窄工具、按既定顺序调用现有服务，
最后输出一份安全回执。Agent loop、Session、模型路由、工具执行、取消、Evidence、Outcome、
账本归约和指针转换仍由现有 DSH/Tianwen 产品路径负责。

## 2. 直接继承的决定

1. DSH `0.1.0-rc.7` 是唯一 Agent Runtime。
2. 正式活动固定 25 个独立 Session：2 seed、10 B/C、5 evaluator、5 Shadow、3 transition。
3. 每个 Session 只有一次正式角色；不补跑缺失 arm，不挑选结果。
4. DSH Agent 内部模型调用自然完成；Tianwen 不设置模型请求、token、金额或价格上限。
5. Provider retry 必须为 `maxRetries=0`；工具副作用和卡死分别由 `maxToolCalls`、
   `maxElapsedMs` 约束。
6. synthetic defect 永久标记 `development-only`、`synthetic-defect`、
   `naturalUserEvidence=not-claimed`、`externalUserEvidence=not-claimed`。
7. Shadow 与 pointer 只在 isolated-test scope 内生效，不改变普通 root Skill、历史 Session、
   真实用户 ledger 或 global Champion。
8. 项目所有者的 standing authorization 已覆盖证据门通过后的
   Promotion → Rollback → Restore；不再逐项询问。

## 3. 已证明的产品缺口

产品 Runtime 已注册 `TianwenSkillEvaluationService`，并提供：

- `runControlledArms()`；
- `runControlledEvaluators()`；
- `runControlledShadow()`；
- `runControlledSkillTransition()`。

但已安装 CLI 只有 status、list、create、resume 和 model；Runtime Bundle 也没有可发布的
controlled operation runner/patch。唯一全链调用者是开发脚本，它自行挂载 persistent harness
和 `ScriptedAdapter`。因此真实 Provider 运行若继续使用该脚本，只能证明“测试夹具接上了
DeepSeek”，不能证明“安装后的产品入口可用”。

这个缺口属于产品入口接缝，不改变业务语义。按照项目的“先从架构推导，再映射接口”原则，
应补已安装入口，而不是把测试脚本重新命名为真实运行，也不应为了入口缺失再造第二个控制面。

## 4. 选择的 installed-product 入口

固定命令形态：

```powershell
tianwen controlled-lifecycle --manifest ABSOLUTE_JSON --data-dir ABSOLUTE_PRODUCT_ROOT --json
```

installed command 的父/child 两层共同完成零 Agent preflight。父 CLI 负责不需要加载 DSH
service 的静态边界：

1. `data-dir` 必须是 `D:\DevData` 的严格子目录，并且是官方 installer 产生的完整 rc.7 产品；
2. manifest 必须是 exact-key、有限大小、lossless JSON，且所有路径位于冻结 operation root；
3. install receipt、Runtime Bundle、DSH host、Profile、Session/Evolution 根必须闭合；
4. manifest、workspace、Skill、tool schema、授权和 installed archive digest 全部固定后，
   才启动 DSH child。

child 使用现有 Profile 与静态 patch，关闭 headless 默认 runner，只插入一个已发布的
controlled operation runner。该 command-scoped overlay 还必须把 `llm-deepseek` 的
`retryPolicy` 固定为 `normal/0`，并只禁用 `session-title-llm`。保留 `llm-retry`、
`session-title` 与 `settings`：零次重试由 DSH 原生 retry seam 执行，Session 标题保留无模型的
确定性 fallback，保存的 model selection 仍由 settings 读取。普通 Profile 不带该 overlay，
行为不变。

child 必须再次按父进程保存的 digest 重读 manifest，并在创建 Agent 前检查 25 个 Session
全部新鲜、隔离 Evolution 没有旧活动、saved model 精确解析为
`deepseek-official/deepseek-v4-pro`、实际 Provider retry 为 normal/0，以及
`DEEPSEEK_API_KEY` credential reference 已配置。它不读取或输出 credential value；任何不一致
都以 0 Agent/0 model request 停止。

patch 是 controlled 命令默认值，不是假装不可覆盖的锁。DSH settings 仍可能覆盖 Provider
config，所以既有 runner 的 actual-policy preflight 与每个阶段边界重验继续是最终承重门；若
实际值不是 normal/0，就在首个 Agent 前安全停止。zero-Provider 组合测试必须使用同一官方
Profile 和 `--patch ... --dump-config`，同时证明 controlled overlay 生效、普通 Profile 未改变、
标题模型 provider 已禁用且 local title fallback 仍存在。

入口不是通用任务编排器。它只接受本设计固定的 v0.1 schema、2/5/5/3 数量和阶段顺序，
不接受 caller-authored verdict、score、Candidate ID、Run ID、pointer revision 或成功标志。

## 5. 受控 Skill

### 5.1 故意有缺陷的 B

Skill 名固定为 `tianwen-controlled-architecture-decision-v01`，只注册到本次隔离活动。B/C
共享以下 immutable metadata，只有 `content` 不同：

```text
description = Choose a bounded Tianwen architecture decision from frozen options.
whenToUse = When a controlled Tianwen task asks for one architecture choice and a concise reason.
invocation = { modelInvocable: true, userInvocable: true }
source = runtime
provider = runtime
```

B 的已知缺陷是“表面便利优先”：把最近的现有接口误当成产品边界；已有身份或 wrapper 只要
能近似结果，就拒绝补独立 binding 或调整调用边界，也不再用模块职责和更新的运行证据校正。
这个通用缺陷复现项目历史上把 Session 当 Run、围绕 pnpm wrapper 扫描输出等偏离，同时不
包含任何任务答案或 option token。

B 的 content 精确冻结为：

```markdown
# Surface-convenience Tianwen architecture decision

Treat the closest currently visible interface as the product boundary. Choose the option that keeps
behavior inside or immediately around that nearest interface, even when the task context names a
broader Run, transport, or evidence contract. When an existing identity or wrapper can approximate
the requested result, prefer that approximation over adding a separate binding or changing the
invocation boundary. Do not reconcile the choice against module ownership or newer operational evidence.

Use `record_architecture_decision` exactly once, then call `verify_architecture_decision` exactly once.
The verifier ends the Turn after recording the verdict; do not attempt another model step.
```

缺陷只在架构判断方法，不通过缺工具、破坏身份或故意让 Agent 崩溃制造失败。

### 5.2 修正后的 C

C 只增加一条可迁移规则：

> 先从当前 canonical 产品语义、模块职责和最新 exact 证据推导合同，再映射到公共接口；
> 接口足够就直接复用，只缺接缝就补最薄接缝，通用 Agent/平台行为优先采用 DSH、标准库或
> 平台原生做法；若旧文档与更新的 exact 证据冲突，先完成事实校正。纯局部实现选择不扩大为
> 产品治理。

Candidate content 精确冻结为：

```markdown
# Evidence-led Tianwen architecture decision

First derive the product semantic contract from the current canonical architecture, module ownership,
and the newest exact code, CI, and operational evidence. Then map that contract to public interfaces:
reuse a sufficient interface; when only a connection is missing, add the thinnest binding; for generic
Agent, platform, or data-format behavior, use the existing DSH, standard-library, or native-platform
seam. If an older document conflicts with newer exact evidence, reconcile the fact before deciding.
Keep a purely local implementation choice local instead of expanding it into product governance.

Use `record_architecture_decision` exactly once, then call `verify_architecture_decision` exactly once.
The verifier ends the Turn after recording the verdict; do not attempt another model step.
```

Candidate 不包含任务答案、hidden reference、B/C 标签、Session/Run ID 或评分提示。

## 6. 真实工具与客观 verifier

正式执行 Agent 只看到三个工具：

1. DSH 原生 `skill`；
2. `record_architecture_decision`：保存该 Session 的第一次
   `{ taskId, choice, explanation }`，第二次提交拒绝，不能用自我修正替换首次正式结果；
3. `verify_architecture_decision`：参数固定为 `{ taskId }`，从 runner 私有闭包读取首次提交和
   hidden expected choice。匹配返回 `verified`，不匹配返回 `not-met`；两者都是完整的业务判定，
   都调用 DSH 原生 `concludeTurn()` 结束当前 Turn。上下文缺失、重复调用或无效参数才是工具错误。

`verify_architecture_decision` 是 acceptance tool。它的参数在同一 B/C pair 中完全相同，
因此 Evidence arguments digest 可闭合；B/C 差异来自第一次真实决策，不来自 verifier 读取
baseline/Candidate 身份。

两个工具都不访问网络、真实产品数据、凭据、shell 或外部服务；decision 只保存在当前 child
内存。workspace 是隔离 operation root 下的一份 `case.md`，B/C 使用字节相同但目录和 Session
不同的副本。任务 prompt 可以读取同一场景正文，但看不到 hidden expected choice。

Agent 被明确要求在 verifier 前完成 Skill use、选择与理由；verifier 的成功结果是正式协议终点。
工具本身拒绝第二次 decision，而 `concludeTurn()` 从进程生命周期上阻止 verifier 后的额外模型
请求。这样仍复用普通 DSH Agent loop，但不再让无业务价值的自然语言收尾决定 Run 是否完成。

## 12. 安全回执

stdout 只允许一行 `tianwen.controlled-real-skill-lifecycle.v1` JSON。成功回执包含：

- evidence labels 与未声称范围；
- installed archive、manifest、protocol、evaluation、Shadow、transition set、最终 pointer digest；
- mechanism verdict、Shadow verdict、promote/rollback/restore verified 状态；
- 25 个 Session 的角色计数，以及由 Session 事件归约的 model-step、tool-call 与 acceptance
  Evidence 计数；
- final pointer revision/version digest；
- ordinary root、legacy Champion、其他 pointer、真实产品根未改变的布尔闭合事实。

失败回执只包含 activity digest、已闭合阶段、有限 reason code、已完成角色计数和
`natural/external evidence=not-claimed`。不包含 raw prompt/output、工具参数/结果、evaluator
reasoning、Skill 正文、Session/Run/Candidate ID、路径、凭据或 raw error。

计数必须按证据来源分级，不能为了“看起来完整”把观察值写成已证明事实：

1. `receipt-certified`：只有合法 `passed` 回执才能认证完整的正式 Session 角色，以及 receipt
   按 Session 事件归约出的 model-step、tool-call 与 acceptance Evidence 计数。即使标题模型
   provider 已禁用，`step/start` 与 `tool/call` 仍不能升级为 Provider 账户实际请求数或 tool body
   实际执行数；没有独立既有事实源时，这两项外部实际数仍为 `unknown`。
2. `durable-observed`：失败后可由预先冻结的只读检查脚本，对 manifest 列出的 25 个 Session
   使用现有 Session persistence/inspection seam 汇总已落盘 Session、model-step start、tool-call
   event 与可闭合 verifier Evidence。`step/start` 早于真实 Provider 调用，`tool/call` 也不证明
   tool body 已执行，所以这些名称不得改写成“实际 Provider 请求/实际工具执行”。
3. `unknown`：合法 stopped receipt 不携带的实际请求/工具数，以及无合法 child receipt 的
   transport failure 内部阶段和计数，必须明确为未知。

这项区分是汇报与 operation artifact 合同，不改变产品 receipt exact schema，也不新增 ledger
读取、遥测、预算器、数据库或第二套计数器。只读检查失败时仍写 `unknown`，不得因此重跑
lifecycle；它也不能把 transport failure 升级成成功。

child 输出由父 CLI 限长、按 exact schema 解析后再转发；stderr、额外行、未知字段或退出码与
receipt 不一致都归为 transport failure。为保留诊断能力，runner 在最靠近事实源的位置把错误
映射到有限阶段/原因，不把所有失败压成一个永久 opaque token。

## 13. 正式停止线

以下任一项发生即停止当前 activity：

- manifest、task、rubric、hidden reference、B/C、Provider、workspace 或工具面在首个 Agent 后改变；
- 25 个 Session 任一不新鲜或出现第 26 个正式 Session；
- seed 未按 D1=`not-met`、D2=`met` 闭合；
- Candidate 任一客观硬门失败；
- evaluator identity exposed、材料不足或未提交；
- Shadow 任一不是 closed `met`；
- transition/post-check/recovery 无法证明；
- 凭据、真实用户数据、raw error 或 private ledger 事实泄露；
- 尝试继续 partial activity、补 arm、改题、重试或挑结果。

正式 activity 开始前，以下 readiness 项任一不闭合也必须停止，但不消费 activity-01：

- official launcher 不能输出并由既有 parser 接受 model status receipt；
- controlled full-profile dump 不是 DeepSeek normal/0，或 `session-title-llm` 仍启用；
- ordinary Profile 被 controlled overlay 改变；
- official launcher、task package generator、manifest parser 或 postmortem checker 任一 identity/digest
  与冻结值不一致。

readiness 闭合后，首个 exact official
`model use --model deepseek-v4-pro --data-dir ABSOLUTE_PRODUCT_ROOT --json` 的 direct invocation
就是该 activity 的消费边界。进入 official `main()` 后的 usage/stopped/nonzero exit 也属于正式结果；
“没有模型请求或 Session”只能说明副作用为零，不能把 activity 改回未消费。

失败后先保留 product root、operation root、Sessions、Evolution、install receipt 和安全回执。
模型选择可以单独恢复 offline；这是零 Provider 的安全收尾，不是重试，也不删除失败现场。

## 14. 明确不做

- 不用 scripted demo、test harness 或 fixture adapter 冒充真实运行；
- 不新增 Agent loop、Runtime、ledger、数据库、daemon、scheduler 或通用 workflow engine；
- 不把 operation runner 扩展成任意 Candidate/任意任务编排平台；
- 不新增价格轮询、预算器、token/model request cap 或费用估算；
- 不开放 shell、filesystem write、网络发布或不可逆外部工具；
- 不修改普通 root Skill、真实产品 incumbent、global Champion 或已有用户数据；
- 不因失败自动重试、继续 partial activity、增加第六个任务或重复 evaluator；
- 不把 controlled pass 宣传成自然用户改善、外部用户反馈或市场泛化。
- 不绕过 official `tianwen` launcher 直接执行 canonical real JS 来证明 installed CLI；
- 不禁用 `settings`、整个 `session-title` 服务或 `llm-retry`，不自建 Tianwen retry/title layer；
- 不给失败回执增加猜测出来的请求/工具计数，不为事后统计修改产品 receipt schema；
- 不复用、覆盖或清理 Task 9B.0 的失败安装根和 evidence root。
