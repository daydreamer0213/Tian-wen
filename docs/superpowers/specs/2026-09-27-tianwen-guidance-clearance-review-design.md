# Tianwen 方法放行审查材料设计

## 当前结论

产品的 `guidanceActivationQuarantine` 继续保持开启。本设计只定义**只读审查材料**：让独立审查者看见某一项已接受研究究竟依据了什么、候选方法在十条试验中写出了什么、哪些判断来自模型、哪些来自原始用户。生成材料本身不得写入账本、改变裁决、解除隔离或触发后续任务。当前没有新的真实模型 `accepted` 且待激活研究；E069 为 `inconclusive`。旧 R9 已激活且有已确认错误，只可作为拒绝样例，不可回填新放行。

## 为什么需要这份材料

R9 的两条候选试验答案包含无来源的确认时间、把已知状态扩大为待定及新增通知承诺。两位原生审核者都捕获了关键句子，却以 `inference/permitted` 判通过；原始反馈中的“助手自己的建议”还曾在研究标准中偏成“用户自己的建议”。E068 在普通任务中又把少量成功样本扩写为链路稳定，双审漏判。后续自动主张拆分诊断会误挡正常建议。因此，增加一次同类模型投票、只看审核标签，或一律禁止推断，都不能作为现在的放行依据。

比较三种路径：继续自动投票保留速度但复现共同误判；永久隔离保护用户但不能验证学习后的任务效果；先出可核对材料、由独立的人就具体研究作判断，增加人工成本，却能在不夸大模型可靠性的前提下获得下一次受控激活的依据。选择第三种作为后续方向；在可审查材料和实际独立判断出现前维持永久隔离的效果。

## 一项研究对应一份只读材料

输入是一个精确 `studyId`、其演进账本根目录和原生 Session 存储。仅当账本只读回放成功、研究为 `accepted`、候选存在、十条正式试验臂完整且未激活时，才生成“待放行”材料。历史已激活研究只能生成醒目标记为**诊断用**的材料，不能转成新许可；其他裁决和不完整研究不生成待放行材料。工具不得执行模型调用或恢复研究进程。

材料必须同时展示并精确绑定：

1. `studyId`、范围、父方法版本、候选方法完整内容及其版本、十臂摘要、`study-decided` 内容与摘要、当前同意修订和来源支持状态。`accepted` 只是模型研究结论，不写成内容安全结论。
2. 两条来源任务和成功对照的原始请求、答案、原任务要求。产品允许来源由原任务的有效 `not-met` 审核支持；这种来源须展示原审核，不能伪装成有用户反馈。若来源由反馈支持，则把反馈原话、准确目标任务、评估分类、改写后的补充标准并排呈现。审查者须能核对说话者、行动者、时间、否定、例外和适用范围；不得只给补充标准而隐去原话。
3. 五个冻结案例各自的原始任务与事实来源，以及 baseline/candidate 两份**完整**试验答案。每臂列出原生执行证明、材料和输出摘要、两份审核的原结论及审核说明；不能以 `met` 数字替代答案。合成 adjacent/holdout 明示为合成任务，不能称外部用户效果。
4. 候选方法可能新增的事实依赖、把已知改成未知、代用户或发送者承诺后续行动、建议与事实的边界，以及当前用户明确要求覆盖旧方法的情况。只记录独立审查者实际发现的具体位置、来源和理由；不预填“均安全”。

材料输出保存在指定的 `D:/DevData` 子目录。清单列出每个输入文件／Session 的 SHA-256、研究和候选的版本及审查材料自身摘要。缺原生 Session、来源绑定不一致、材料重建不符、反馈原话无法恢复、任一候选答案缺失时输出失败事实并停止，不生成可签字的摘要。敏感原文仅留在本地审查目录；Git 只保存设计、测试和脱敏结论。

## 独立判断与激活的后续边界

审查者必须基于完整材料单独记录 `clear`、`reject` 或 `insufficient`，并对每条候选试验注明事实边界与反馈忠实性结论。任一明确错误或证据缺失不得 `clear`。R9 的 source1、source2 候选错误及反馈主体偏移必须使这种审查返回 `reject`；正常天气推断、可选建议和请求的虚构不得仅因不是来源逐字复述就自动拒绝。这个历史样例只用来检查审查尺度，不替代下一份真实新研究。

本阶段**不实现**审查者身份、签署界面、`clear` 账本事件或激活通道。后续若有具体待激活研究和实际审查记录，再设计一次性、精确绑定 `studyId`、候选版本、裁决摘要及材料摘要的许可；激活前还须重新核对同意、来源支持、父版本和材料身份。不能让模型调用一个自称“人工批准”的工具自行放行。没有这种端到端证据前，产品 bundle 继续拒绝所有新激活，main/Daily 继续 NO-GO。

## 最小验证顺序

先用旧 R9 只读快照做**诊断模式**原型：它应完整呈现十臂和两处错误所需的原始请求、答案与反馈，标明历史已激活，且不改历史账本。再用一份脚本化的已接受但未激活研究检查材料缺失和摘要绑定；这只能证明机制。真正“待放行”验收必须等下一项自然产生的真实研究，从准确包、新冻结输入和新 Profile 首次运行取得，不能重复旧题凑出 `accepted`。完成独立审查后才可能讨论受控激活和一次未来任务；一次未来任务也不能证明长期改善。

R9 的现成盲评对照给出了可证伪的诊断预期：十臂中 source1/candidate 与 source2/candidate 虽各为原生 `met/met/met`，仍须展示“周五后才能基本落定”的无依据依赖和“这些都等核对才有准信”的过宽指代；source2 的原反馈“你自己的建议”必须与改写标准“用户自己的建议”并排可见。若材料只列模型通过率或无法显示这些原文，就尚未达到本设计的第一阶段目标。相关历史证据见[原生与盲评对照](../../operations/tianwen-natural-conversation-acceptance-r9-results-20260908.md)，其原始详细对照保存在 `D:/DevData/tianwen-native-claim-capture-20260908/r9-first-study-semantic-comparison.md`。
