# 天问带原句语境的来源复核：先证伪，再接入

## 要解决的缺口

现有产品 `runConversationClaimReview` 已经把原请求、完整答案、逐项审核记录和两份独立原生证明留在同一路径。其记录在旧 R6-W3 中摘到了“后才能确定能否照常办”，却分别标成 `inference/permitted` 和包含该关系的 `source-fact/supported`，最后双 `met`；036-S1 的“该阻塞未被本轮 132 项测试通过所覆盖”也被摘到并标成可接受推断。问题主要是**已发现的来源关系被错误放行**，不是缺少另一个答案切片器。

新答案侧提取试验把正常 T5 建议的理由“方便看清有哪些东西”误标为独立事实；产品原审核却保留了完整建议句并正确放行。因此不把该提取器接进产品。直接把所有 `inference/permitted` 判待定也不可取：旧正常 W8 有两条建议理由会被选中，六份新自然答案有五份含推断；这会显著缩小正常可用范围。以两个审核员的分类差异作硬门槛也会波及正常 T3/T6。旧题并不构成新方案的前瞻验收。

## 方案比较与选择

1. **新答案侧拆句再逐条判断**：有机会指出旧必要条件，但会丢建议语境；八题全查时已有正常误拒，六题新答案仍复现错误。停止该路线。
2. **宿主对推断或审核差异直接降级**：无需额外模型调用，却会把大部分普通进展答复挡在学习证据之外，且不能可靠区分必要条件与建议理由。停止该路线。
3. **带原句语境的定向来源复核**：从现有两份审核记录取候选，保留每个候选所属的完整原答案单元、原请求及真实工具来源，另用一次独立原生调用判断；仅在候选层核实能否同时指出旧风险和放过正常建议。先做隔离诊断，达标后另立产品接入门槛。选择此项。

## 本阶段的最小实验

本阶段不修改主审核函数、学习账本、UI、Daily 或主线裁决。一个独立诊断使用当前生产证据投影 `projectClaimEvidence` 和原生 `runConversationJudgment`；输入为此前已冻结的原请求、完整答案与双审核结果。控制标签单独保存，不进入模型材料。

候选选择是确定性的：只在现有双审核汇总为 `met` 时，从两份审计中取 `kind=inference,status=permitted` 的精确原文引用，按 `(answerId, quote)` 完全相同去重，**不按子串包含删除**。引用必须能在所属答案单元找到；模型同时看到该完整单元及原始来源。正常建议理由即使被选中，也应由来源复核识别为建议的理由，不能当作已经发生的事实。单题候选超过 12 条、引用无法定位、原生证明不可恢复时，本次诊断记为 `inconclusive`，不重抽或补造答案。

一次原生调用返回每条候选的独立判断：`source-supported`、`permitted-advice-or-fallible-inference`、`unsupported-source-dependent` 或 `uncertain`，附精确引用及理由。诊断审计必须恢复原生会话，核对输入材料、模型配置、请求和会话摘要、候选顺序、输出枚举与引用。不依据模型自述代替证明。

旧题只作**可行性证伪**：036-S1 的测试覆盖判断、R6-W3 的“电话后才能确定”若再次被放行，本方案立即停止；正常 R6-W8 的建议理由若被判无来源的既成事实，也立即停止。T4 已由来源明确提供的周三法务必要条件与 T6 保留未确认状态用于观察误拦。无候选的正常 T5 不额外调用。所有题只取第一次结果，失败按失败记录。即使这一小组通过，也只说明值得进入新冻结自然任务的前瞻试验，不能自动改产品审核。

## 后续产品接入门槛

若本阶段通过，先按实际候选数和观测耗时确定上限，再冻结新的自然任务、明确风险与正常对照，运行产品任务生成、现有双审核及定向复核，单独统计漏放、正常误拦、未能判定和调用量。产品接入时必须沿用观察器的原始材料与同意边界，保存第三份原生证明，重启后可核验；仅在第三份有疑点时把**学习证据资格**降为 `inconclusive`，不得把它直接解释为用户答案错误。历史记录不重评，质量合同需要新版本，主线与 Daily 在真实端到端门槛通过前仍 NO-GO。

本阶段明确不承诺：现有审计能枚举全部错误关系；一次定向调用能证明来源真实；通过旧题等于新任务稳定；诊断调用耗时等于产品时延。这些是后续验收必须回答的未知。
