# E041 后续：缩小逐条审核中的来源 ID 参数

## 已验证的问题

E041 第一原生审核成功捕获了六条有效摘要引文，但逐条审计的一条引文跨越回答单元，宿主正确拒绝。原生会话另显示：`evidenceQuotes` 已是无枚举字符串，而整份 `structured_output` 参数模式仍达 1,357,234 字节。模式对每个回答单元重复列出全部来源 ID；本次证据投影有 1,153 个单元、回答有 64 个单元。它没有在 E041 直接造成失败，但会增加调用体积，也可能放大未来的参数错误回执。

## 选择与边界

可以合并所有回答单元到一个自由形式审计对象，模式会更短，却失去原生工具对每个单元必填的提示和校验。此次仅把每条主张的 `sourceIds[]` 元素从重复枚举改为普通字符串；当没有任何来源时仍要求空数组。保留现有回答单元键集、主张字段、原生捕获和 `validateClaimAudit` 对每个来源 ID 的实时校验及冷恢复校验。无效 ID 在宿主处形成 `invalid-judgment`，不会成为成功审核。绝不以放宽跨单元引文校验追认 E041。

## 验证

先在包含约 757 行来源、64 个回答单元的工程场景复现 1.25 MB 模式，再要求模式低于 200 KB；另用原生工具接受无效来源 ID 后，证明宿主在第一审核结果处拒绝它。相关复核测试、类型检查和差异检查通过后才固定新候选。下一次真实模型验收需新的隔离配置档与新任务；E041 仍保持失败关闭。
