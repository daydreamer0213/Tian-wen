# 普通代码任务的前置检查合同与独立结果记录

## 目的与取舍

基线 8eabd59 已能在可控开启下捕获普通 external/code 的原生文件输入/输出。缺口是：检查合同未在答案前与原任务绑定，独立结果也没有持久位置。继续用模型 review 存独立结果会混淆判断来源；另造 Outcome/验证器注册表会重复现有任务恢复。因此复用 ConversationLearningRecord，新增两个有限记录和一个宿主程序接口；不改变研究或激活许可。

此次只实现接线机制及反例，不重跑上轮已完成真实任务，不合成用户反馈、不将机制夹具当真实学习效果。随后仍须用新的实际未完成任务及候选之外的适用检查验证此入口。

## 信任与接口

宿主程序配置可提供唯一的 `externalCodeCheck.prepare`，没有 UI/JSON/模型工具注册。配置不提供或文件捕获开关未开启时无此分析。prepare 收到原请求/原上下文/任务/模型配置身份，不收到候选；返回 undefined 表示此检查不适用。

返回的 prepared check 给出 checkerId、checkerDigest、contractDigest、冻结的目标文件原始内容，以及只检查已捕获输入/输出的 evaluate 闭包。原始请求适用性与实际覆盖由该宿主检查实现承担；元数据声明不证明独立或完整正确。闭包不得执行生成代码或依据当前磁盘补检查来源。没有安装的具体可信适配器就不声称普通任务独立验证已成立。

## 时序与记录

1. 普通 observer 首次准入持久后、首次根模型请求之前，await prepare；宿主冻结合同与文件原内容，持久写 `task-external-check-prepared`。记录绑定 taskId、原请求/上下文/准入摘要、模型配置摘要、原生 preparedSeq、检查身份和排序后的目标输入摘要。已经有模型观察/文件调用/完成结果时不能准备，不能改合同。
2. 原任务按现有方式执行，不向模型注入新格式或让它提供检查标准。完成后先确认原生保存成功，再通过既有 exact native span/调用/结果恢复输入/输出；与准备时文件摘要、模型身份、时序相符后，才调用已保存闭包一次。检查后再次确认保存及原生身份，保存失败只记不可核验，保存等待可取消。
3. 写 `task-external-check-finished`，单独保存 prepared 记录摘要、完成结果/文件结果摘要、`verified|rejected|unverifiable` 及有界说明。这些状态只表达该检查结果，不变成模型 met、accepted 或激活许可。
4. 完成/恢复可独立于模型 review；失败、丢闭包、原生变动、模型漂移、输入变动、文件证据不可用时不调用检查器，记录 unverifiable。进程重启不能在答案后重做 prepare；缺闭包时只写不可核验。撤回同意不继续调用或写新分析结果；写入与冷重放共用记录发生时的同意检查，历史合法记录保留。现有记录保持不可改写/重复幂等。

## 有界性与历史

仍是唯一 Evolution 账本，新增记录字段严格解析，说明<=4096 UTF-8字节，目标文件沿用8文件/96KiB单文件/128KiB总量。只保存准备摘要，不重复全量冻结依赖；依赖读取闭包归具体可信宿主检查持有。原 Task 与 review 模型语义完全保留，无文件的旧 external 任务不回填。当前可信检查能力声明与真实模型/自然学习效果分别记账。

## 验证故事与停止条件

正常：原生普通任务准备前置合同→未知原生文件修改→精确恢复→一个确定性检查按冻结材料判定→两个记录冷回放相符，模型 review仍inconclusive。

反例：模型输出之后/文件调用之后注册合同、改原要求/输入/模型/完成摘要、非external/code、关闭捕获、未准备、撤回同意、假model met→拒绝或不执行；结果不能因字段声明扩大权限。

失败：prepare失败不阻塞普通任务；检查抛错/数据太大/完成原生证据失配→unverifiable；已持久prepared但闭包丢失时不重新prepare、不重新执行；首次不确定结果不能覆盖为verified。机制测试不是可信适配器或完整学习证明。
