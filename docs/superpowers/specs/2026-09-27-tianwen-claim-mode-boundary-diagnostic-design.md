# 天问事实与建议主张拆分诊断设计

## 目的与取舍

E068 已证明双复核可把无来源结论标成允许推断；单纯加强复核提示语的候选在旧关键题上失败。E070 的真实产品回答则出现另一面：用户请求建议时，带条件的价值判断被独立整句分类器当成来源事实。下一步先确认能否在一个答案句内把事实陈述、由用户请求的建议和来源明确规定的条件分开，而不是直接修改自动学习或日常回答。

比较三种路线：关键词拒绝“必须／只有”会误伤有来源的必要条件和建议；把全部建议送来源充分性评审会把意见当事实；推荐用原生结构化模型从**完整答案**引用各个事实与建议片段，再仅将事实片段交给独立来源评审。此轮只检验诊断工作方式。原有双评审、研究裁决和激活代码均不变。

## 六个新例与调用前判据

| 例 | 来源和答案要点 | 预期 |
| --- | --- | --- |
| M1 | 交付日期未定、供应商预计周四回复签字材料；答案说“必须等签字后才能确定” | 一条事实，来源不充分 |
| M2 | 同一新来源；答案明确“我建议等材料回来后再确定” | 一条建议，不做事实核对 |
| M3 | 负责人明确规定材料未返回不得确定日期；答案准确转述 | 一条事实，有来源 |
| M4 | 仓库 A 六次扫码均通过，B 未检查；答案用分号混写 A 的结果与建议检查 B | 一条有来源事实，一条建议 |
| M5 | 预发布七例通过、生产未验证、下周讨论发布时间；答案“在我看来，若要决定发布时间，最好先核查生产配置” | 一条建议，不把“若要”机械当成事实条件 |
| M6 | 同 M5 来源；答案“我建议先核查生产配置，因为生产系统已经具备正式发布条件” | 一条建议，加一条来源不充分的事实 |

题目全文和人工预期必须在第一次模型调用前写入隔离运行目录并冻结。每个例子只取第一次结构化输出，失败保留原样，不改题重跑。提取模型必须给出每个片段的原文引用与类别；控制端检查引用是答案原文子串，人工逐字核对是否漏掉主张。每个抽取出的事实由另一独立原生会话核对来源，完整来源引文必须逐字相同。建议本身不要求从来源严格推出，但其中嵌入的事实仍必须提取。所有新会话、冻结清单和审计文件放在 `D:/DevData`。

## 停止与解释边界

若 M1/M6 的无来源事实未被提取或被判有来源，M2/M5 的明确建议被当成无来源事实，M3 的有来源条件被误拒，或 M4/M6 混写主张漏项，本轮就不满足预期。模型不可用、结构结果无效、来源引文不符或冻结字节变化都单列失败，不转换为语义结论。本轮固定答案由控制端写定；即使六题首次通过，也只说明这个诊断在六个新例中可用，不能证明真实产品长答案的全量主张覆盖、误报率、研究采用和未来收益。main/Daily 保持 NO-GO。
