# 原评审提交修正

所有者允许主动模拟缺失条件并自主修复，阶段通过即收口，不索题或增加自然等待。

100 次真实请求的新投影批次未进入研究：三训练答案均通过实际 Python；K 双审通过，L 第一位字段错误在原会话已修正且证明可恢复，但第二位仅输出普通文本无捕获；M 的三条摘要引用跨证据片段，原逐项包含检查拒绝。原历史不补评，不把这些答案标失败。故障漏掉 get_goal 回读使训练任务恢复原要求，实验应另行修正，不能通过改旧结果解决。

本阶段只修复可恢复的原评审提交错误。采用现有 tools/pre-execute 接缝和原 turn-stopping 一次提醒，保留完整原材料、独立两会话、成功捕获、模型配置和所有后置谓词。另起评审会丢掉原尝试，放宽引用会改变证明要求，因此不采用。

所有 claim review 的原摘要/答案引用在成功捕获前校验，错误只返回位置及复制要求；仍失败则原终态不可核验，绝不替模型修文。原审计其他错误仍按原谓词拒绝。漏 structured_output 且无任何工具尝试时，仅注入一次固定 review 专用插件提醒；证明恢复只允许这个精确提醒、原顺序、一个原用户要求、一次成功捕获和同配置，拒改文/来源/额外消息/多次提醒。已有无提醒证明保持兼容，不新增模型裁判或批次重试。

验收：实际原 SDK 测试中普通文本→一次提醒→成功捕获、非法引用→原工具拒绝→修正成功，两独立证明可恢复；非法提醒、原答案/摘要非法引用未修正仍拒绝，旧错误字段修正和默认评审回归保持。阶段无真实模型收益宣称；下一新的冻结受控问题沿原机制执行。
