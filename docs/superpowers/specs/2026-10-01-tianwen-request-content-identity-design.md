# 自然任务的内容身份与消息身份分离

## 新事实与修正

49f6ea8 后继续核对来源去重，发现 observer 的 requestDigest=sha256(direct) 包含每次不同的消息编号。它是准确来源绑定，不能直接代表请求内容不同。上一轮相同输入不触发回滚的机制用例人为令请求摘要相同，没有覆盖实际消息编号；不能把它作为自然重复输入保护的完整证明。前像归一化/历史回放仍有用，但需修复内容身份。

现有文本来源扫描、账本来源检查及回滚都在部分位置使用请求来源摘要；相同内容的新消息可能被当作不同来源或不同退化任务。文件来源还可能因读取顺序/大小写不同获得不同身份。这是原“两个不同输入”规则的缺口，不增减来源资格、不引入语义独立证明。

## 方案

不删除消息编号，不改 requestDigest，也不改已持久化案例的 inputDigest 算法。准确来源身份和内容身份分别保留。

在新 task-started 里增加可选 requestContentDigest，普通 observer 在任何分析/候选前从 direct.map(message=>message.content) 计算。完整内容块和消息边界保留，不做文本拼接、空白归一化或丢弃非文本内容。内容摘要排除消息/会话编号；原请求摘要仍保留这些编号用于来源校验。恢复材料时同时核对两项，旧缺字段记录不补写。

复用文件前像身份函数，允许显式请求摘要参数；默认优先新内容摘要，缺字段保持旧行为。新增统一任务输入函数仅支持有内容摘要的 text 或完整 local-files：文本用原内容摘要，文件把内容摘要与归一化前像组合；缺材料/不支持模式不推断身份。

研究扫描优先这个身份；旧文件材料已准确恢复时从完整原请求内容计算并配归一化前像，不改旧任务。旧文本来源规则保留。账本新尝试/打开/激活，对两个均有新内容身份的来源额外核对不同输入；仅新写生效，历史重放/重复幂等及 shared support 不重判。混合或旧记录仍受原规则，不能声称所有历史材料已具备新的独立证明。

后续 regression 新写统一携带 evidenceInputPolicy=request-content.v1，text 和 local-files 都按新身份核对，仍要求两次真实 not-met 及原版本/模型/族/模式/质量/作用域/时间规则。新运行时仅选有完整新内容身份的证据，不用旧消息编号补成两个不同输入。已保存的无字段 request-only 或 captured-files.v1 回滚继续准确按旧语义重放；v1 文件回放显式传旧 requestDigest，避免新默认值改变历史意义。其他回滚原因、当前任务方法冻结、关闭同意/支持撤回不变。

## 取舍与边界

消费端只删字段但不保存可信内容身份，账本无法同样判断；重写所有旧摘要会破坏原始证明。选候选前的一项内容摘要与既有回滚政策扩展，无新检查平台、模型评审、调度器或执行环境。没有新摘要的旧任务不作为新 regression 证据，但原终态/反馈/历史回滚不变，新的普通任务均自动记录，用户不需重复提交旧任务。

这只排除同内容/同前像被编号、顺序或大小写伪装成不同输入。不同内容摘要不证明事实、语义或因果独立；E104/R9 缺口和完整发布门槛仍在。观察模型 met、不利反馈和 configured check 的原资格保持。
