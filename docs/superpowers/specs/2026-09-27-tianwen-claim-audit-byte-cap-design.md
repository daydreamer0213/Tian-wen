# 完整逐条审核记录的字节上限

## 触发与目标

E045 的受控真实任务产生 114 个回答单元，其中 78 个非空单元各有一条主张。第一位原生审核者第二次提交的结构化结果通过工具模式，但审核记录序列化后为 43,152 字节；宿主的 `parseClaimAudit` 仍把 32 KiB 当作整份审核上限，于是记 `inconclusive / invalid-judgment`，第二次独立审核未启动。该结果不是双审核通过证明。

目标是让这一类仍处于既有 128 单元、512 主张及 32 KiB 答案界限内的完整审核记录进入宿主逐项核验，同时继续对异常大的记录失败关闭。不得截断回答、主张、引文或来源；不改变历史任务判决。

## 取舍

压缩或裁剪审核解释会损失逐条可追溯内容；按回答单元分批审核需要重做原生证明和共识协议。仅把整份审核记录上限从 32 KiB 调至 128 KiB 是本次最小的有界修改。候选模式、引文逐字匹配、来源 ID、主张状态、两次独立审核与恢复校验保持原样。超过 128 KiB 继续拒绝，不把上限取消。

## 验收

先用 114 单元的有界记录重现旧上限的拒绝，再使该用例通过；保留超过新上限的拒绝测试。对 E045 已封存的第二次原生输出做离线宿主校验，只能用来定位根因，不能追认 E045 为成功。代码和完整回归通过后，必须冻结新提交另做前瞻真实任务，才可判断新上限是否真的让两次独立审核完成。自然文件查询证据仍是另一条未完成线路，main/Daily 继续 NO-GO。
