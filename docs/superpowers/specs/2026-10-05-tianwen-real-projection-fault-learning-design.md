# 真实模型任务投影故障下的受控学习

## 所有者要求与当前依据

所有者允许主动模拟问题、失败环境和未知后续任务，不等待自然重复问题；执行者自行准备，不能为了形式限制停止开发。此前受控脚本完整闭环与实际委托绑定阶段均已收口。当前真实模型尚无研究/激活/后续收益的整链证据。复用 5afeb7cb 的公开普通/研究工厂及标准 DEV 接线，完整目标继续 active，main/Daily NO-GO/R9/原发布要求保持。

## 选择

纯脚本闭环已经证明机制，再重复不能回答真实模型效果。以复杂文件缺陷开题会引入不必要的工具环境差异。选择操作员侧可追溯的任务投影故障：旧适配器遗漏原整体输出要求，将实际委托还原为旧格式请求。这个类别与近期发现的原要求传递问题相近，但本次故障是人为模拟，不能称当前产品自然发生了此缺陷。

故障函数只作用于普通原生 Task 与研究的文本执行请求；识别完整原 Goal/独立案例中的 ORIGINAL_RECORD，固定生成旧格式任务投影。保留原数据；未全部 passed 的记录使用旧四属性 project/status/build/tests，全部 passed 对照使用两属性。原整体要求固定为恰好 project/status，failed 仅原判据明确失败，passed 仅全部明确通过，其余 pending。故障不改任何模型回复、不看 baseline/candidate 标志、不看方法内容，不控制答案和研究结论。研究设计、提案和双盲判断不受故障；实际输出仍由同一真实模型产生。

原 SDK 事件/来源/材料/规则保持；投影前后完整请求、摘要和命中类型另存受控收据，使操作员投影与原生请求的差别可核验。故障保持不变，候选唯一变化仍为原机制提供的方法。方法是否能弥补遗漏由实际结果判断，不能保证启用或改善。此证据范围只是指定投影故障和受控任务，不是自然使用或开放语义普遍收益。

## 固定阶段与失败处理

新专用 DEV 小 Profile，复用标准 CLI/base/Web/Loader/真实 DeepSeek，原公开 Python 工厂、缓存镜像和既有源历史保持。

1. 先无同意执行四个未知后续任务的原基线。训练和未来数据事前冻结，未来不进入研究材料。
2. 开启原学习同意，运行两个不同完整原 Goal 问题与一个正常 Goal 对照；每 Goal 一个 Task，规划器自行写委托。旧投影不依赖其逐字格式。保留首输出与独立结果，不能把真实成功改记失败。
3. 原来源选择/研究自动运行；完整五案例与检查规则在提案前固定，前三由实际原 Task 材料绑定，邻近与 holdout 固定。沿原五案例十臂、两独立模型评审、实际隔离结果、原裁决与自动激活。
4. 如实际激活，四个新任务在同故障/模型/权限/环境下再运行；核实实际方法提供记录及结果。再撤回原同意检查回滚，有限受控重复用于比较，不计额外独立问题样本。

新记录分别包含 pending、unconfirmed、null、明确 failed、完整 passed 边界。冻结总体 30 分钟、单 Goal 8 分钟，超时保留当前真实句柄/状态及首失败，确认终态后排空；不因观察超时另起相同任务。机制拒绝无效方法、错误案例或不可核验判断属于结果，定位具体责任继续，不向所有者索题/反复整体 blocked，不事后加样本或换判据使本批通过。
