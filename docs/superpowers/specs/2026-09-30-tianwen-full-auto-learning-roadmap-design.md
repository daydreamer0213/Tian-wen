# 天问完整自动学习：分阶段实现路线

## 授权与目标

项目所有者于 2026-09-30 要求规划完整自动学习，并开启目标模式持续推进；此前已授权不反复停下来确认执行细节。Codex 目标现为 active。本文件不是完成证明，也不改变 Daily 的分析同意。

最终目标仍是：真实任务 → 可归因反馈／重复问题 → 独立研究 → 有效方法 → 受治理自动激活 → 新任务实际使用与效果核验 → 必要时回滚。不能把人工批准、受控脚本、更多模型自评或一类简单任务的成功当作完整自然自动学习。

原十个工作日窗口仍是决策期限，不是完成承诺；新目标不重置窗口。到期必须明确已有交付、研究实际结果及继续／停止判断，不机械续期。

## 三条路线的取舍

1. 继续以同类提示／第三模型复核补洞：没有新的可靠性依据，不选为实施主线。
2. 每个方法由人批准：可以是人工辅助研究，但不能交付本目标要求的自动学习，不替换目标。
3. 在既有研究旁路内引入与模型评分独立的任务结果证据：选作**待证伪的实现假设**。先在可检查结果上做小原型，再决定是否值得接入。它对一般写作的主体、因果、承诺和例外没有自动解决能力；开放文本语义安全仍是最终缺口。

主流评估实践也区分程序检查、模型判断和人工校准：程序适合具体可检查结果，但不擅长开放任务的细微含义。[Anthropic 原始说明](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)。这里只借用分工，不引入外部服务、SDK、评审平台或新依赖。

## 第一阶段具体边界

新增实验模块 `scripts/learning-result-verifier-probe.ts`，只读取调用者提供的结构化值及已恢复的 `ConversationFileEntry[]`。预期值由已有 `capturedFileFacts()` 从 UTF-8 内容计算，不接受模型给出的预期值，也不读取当前磁盘代替冻结来源。

接口：`verifyCapturedFileFactTable(value: unknown, inputs: readonly ConversationFileEntry[]): FileFactVerification`。返回 `verified`（仅该表匹配）、`rejected`（可检查对象不匹配）或 `unverifiable`（没有完整可信输入或不支持该表示）。

支持的值为 `{ files: [{ path, bytes, lines, sha256 }] }`，闭合字段、全部文件恰好一次、顺序不限。来源为空、缺文件内容或路径重复时不可验证；模型侧字段变多、少文件、多文件、重复文件、值或类型错误时拒绝。自然语言字符串不经模型转换后当成表来验证。

本原型只检查**结构化对象**，不解析整份自然语言答案，不判断其其他内容，也不证明该表就是用户原需求。成功不得写成 `met`、accepted、激活许可或语义安全。没有任何生产导入、工具注册、账本事件、后台调用或 Daily 更新。

## 执行与资源

复用 `codex/conversation-claim-evidence` 工作区、现有 Node/pnpm/Vitest 和 DSH，所有生成物在 D:/DevData。先写有意义的反例测试并保存首次失败，再实现、定向验证和只读审查。运行只保留日志、源码身份、摘要与必要原生证据；不新建整套 Profile／依赖／桌面副本。

真实反馈必须来自实际读后反馈，控制器不得代写用户反馈或候选输出。对未经验证的语义保持不确定；持续推进不是无限循环测试，也不是解除同意和激活边界。
