## Decision and evidence

Continue the already-authorized total-route Task 3 with one bounded protocol
revision, not a benchmark platform. The real procurement task produced an actual
scope-generalization defect and a genuine Candidate. Its immutable old evaluation
`evaluation:91783db782a43c9e9fc1f052a887dcaf7d55c0671a96e579dbf295bb33f1db58`
completed ten real Runs and rejected five met/met ties before blind review.
That outcome remains final. It neither proves a prose improvement nor measures

The independent-environment module-identity fault is repaired separately. Do not
change native scope mechanics or serialize lookups as part of this task.

## Alternatives

1. Keep the old questions and wait for an ID failure. This does not measure the
   demonstrated prose defect and would make acceptance depend on an unrelated
   failure.
2. Let ties reach blind review but keep the old ID-only holdout. This still cannot
   detect semantic overfitting on unseen material.
3. Move the holdout before aggregate review to retain thirteen Runs. Independent
   architecture review found this requires a new pre-blind plan/receipt, a result
   dependency cycle workaround, and new Shadow-readiness derivation solely to save
   one Run. Combining the single Candidate holdout with X/Y rows also risks role
   inference through content/style correlation.
4. **Selected after review:** preserve the existing order: ten paired Runs, one
   aggregate blind review, one Candidate holdout, one independent holdout quality
   review, and one activation Run. The source-fidelity path uses at most fourteen
   Runs. The extra Run measures unseen semantic overfitting inside the existing
   holdout gate; it is not a fifth gate or repeated review of paired data. Legacy
   remains thirteen Runs. This explicitly amends the earlier thirteen-Run target
   only for the evidenced source-fidelity policy.

## Source and freezing boundary

This applies only to future, newly frozen protocols for the existing supported
research-summary contract. Old protocols/results/Shadow records retain their
original exact bytes, digests, interpretation and replay behavior. No migration or
regrading of the completed procurement Candidate is allowed.

The new source-fidelity policy is scoped to newly frozen explicit-feedback
analyses, which have the exact message/feedback-version identity demonstrated by
this defect. Outcome-origin analyses have no feedback target and retain the
existing legacy product protocol; do not invent feedback or make that previously
working route protocol-unavailable. A future Outcome semantic-policy revision
requires its own demonstrated need and source-binding design.

Before materializing a new Candidate, recover a transient source-case from the
exact native main Session and feedback target. Reuse the existing packet recovery
by acceptanceSubjectDigest and canonical accepted-submission projection. Verify
the feedback target's completed turn, accepted product call and evidence closure;
ambiguous, missing or unrelated material cannot be silently replaced by old
questions. At this time LearningCase is not materialized yet, so use the retained
analysis/Ticket/source identities, not getLearningCase on a nonexistent object.

The original paired task uses that exact packet. The adjacent task is a fixed
source-fidelity transfer packet defined before any new Candidate; the existing
regression, extraction-counterexample and safety task classes remain. A distinct
fixed source-fidelity holdout is absent from all paired inputs. Freeze their
ordinary task/config/tool/workspace/material digests before Candidate creation.
Do not derive tasks from Candidate text, a desired winner, or a reference answer.
Do not pass the feedback note, historical answer or Candidate patch to the paired
models or blind evaluator. Raw source content stays in native Session/Runtime
material, not new Evolution text stores.

## Versioned pass contract

Retain the five task classes, exact parent/config pairing, native tool allowlist,
ID hard gates, accepted canonical submission requirement and the current 0–4
quality anchors. Preserve the old four quality dimensions and their aggregate
non-regression rules unchanged.

For the new version only, ID ties may proceed to quality review, but are not
improvement. Candidate not-met, any objective regression or inconclusive material
still blocks. One new rubric dimension, `source-fidelity`, evaluates the actual
submitted prose against its packet: attribution, strength and scope of claims,
local rather than blanket uncertainty, temporal limits, and fictional/hypothetical
context. It is scored with the same 0–4 anchors, not keyword/reference-answer
matching.

The existing single aggregate blind Run receives five randomly mapped X/Y pairs.
It sees the exact packet and
accepted canonical submissions, never role/version/Candidate/source identifiers
that reveal the expected winner. Its strict bounded submission includes the
existing four dimensions plus source-fidelity for every presented material.

The new evaluation decision (paired plus blind quality) requires:

- all Candidate objective hard gates pass, with no objective regression;
- original-task Candidate source-fidelity exceeds baseline by at least one point;
- no other paired task has lower Candidate source-fidelity;
- existing four-dimension Candidate total is not lower and no existing dimension
  drops by two points, retaining the old quality protection;
- all material, native evidence, role mapping and configuration bindings verify.

A passing evaluation only permits entering Shadow; it is not promotion readiness.
The new Shadow gate runs its unseen Candidate packet once and then one independent
semantic reviewer with only that packet and its accepted canonical submission.
No X/Y pair, patch, historical feedback, role/version identity or desired answer
is supplied. Shadow requires ID oracle met, source-fidelity at least 3, and each
existing quality dimension at least 3 (goal met with only minor fixes). Both the
native product receipt and independently persisted semantic observation must be
bound before the new Shadow result can be passing/ready.

Insufficient, tied or negative evidence is terminal non-promotion, not an excuse
to choose a new answer, repeat a completed arm or weaken the gate. A positive
result is targeted single-protocol evidence, not statistical or universal efficacy.

## Holdout ordering and immutable version dispatch

Keep evaluation → Shadow → transition ordering. Extend the new Shadow version
with its frozen semantic-review contract/session identity and exact native
observation. Never record an ID-only passing Shadow result and attach quality as
an afterthought. Reuse existing native evaluator execution, Evidence validation
and transition mechanics; no pre-blind plan/receipt, second scheduler, generic
store, new provider, evaluator agent family or direct pointer shortcut.

Runtime recovery must dispatch from the retained frozen protocol version, not
just scopeKey or the latest builder. Keep old task/rubric definitions. Before a
new protocol exists, its source builder accepts only explicit source identity,
packet, configuration and fixed packet-version inputs, never a complete analysis
submission or candidatePatch. Analyst patch text already exists before
materialization, so timing alone does not prove input independence. Verify the
actual feedback target turn; do not copy Outcome's turn-1 assumption.

Promotion still requires the complete new Shadow proof and the existing native
post-promotion activation check. Old v2 Shadow and transitions remain replayable.
Completed native receipts are reused exactly. If partial work cannot be resumed
safely, retain it and report inconclusive rather than starting duplicate arms.

## Tests and boundaries

Tests must first demonstrate the specific ID-tie/prose-fidelity blind spot and the
old Shadow ordering barrier. The new policy then detects source prose regression
and unseen semantic overfitting while preserving all old-v2 rejection/replay tests.
Mutation tests cover false improvement, swapped roles, foreign/missing holdout,
prose drift after submission, stale source identity, missing source, premature
activation and duplicate completed work. Account for fourteen successful-path Runs
for source fidelity and thirteen for legacy; no fifth blocking gate is added.

Test fixtures may exercise deterministic branch outputs, labelled as mechanism
coverage. Genuine acceptance remains ordinary UI with real DeepSeek responses.
Scenario C or D is not presumed to fail; only an actual defect and native feedback
may form a new learning analysis. Approved external reference stays read-only,
and reuse/activation must be independently observed. No daily installation,
package publication, old ledger mutation or automatic source trust is authorized
by this design. Second-generation parent resolution remains a separate task.
