# 可复用独立结果检查：先补交付接缝，不等待自然失败才能开发

## 路线纠偏

所有者要求认真判断缺口、自主推进，不反复把问题退回。既有持续执行授权适用于本设计及常规 DEV 实现细节，无待补执行许可。

此前有限公开三题51案例全部通过；对该固定测试组没有剩余可测改善空间。它没有触发研究，不说明所有工程工作必须等待用户供题。连续来源为空的状态审计不再作为下一开发任务。

当前原生任务/反馈/研究入口已经存在。独立功能检查虽已有实现及真实受控执行，却位于 `scripts/conversation-isolated-python-check.ts`、`scripts/isolated-python-cli.ts`，普通与研究接入由每轮 D: 驱动直接导入工作区源码完成。Runtime 包根公开的是检查接口类型，发布 files/exports 没有具体功能生产者。没有把这一事实扩大为“产品没有任务或反馈入口”。

## 比较与选择

1. 继续挑题期待自然失败：受样本难度/随机结果支配，不解决实验接线的复用问题。本轮不选，不追加旧pilot。
2. 自造负面反馈或预先写错误候选启动研究：可以在明确标注的工程夹具中检查机制，不能生成自然学习证据，也不能满足发布。不得拿它替代最终目标。
3. 先把已有可信检查作为公开可调用的具体适配器交付，再接 DEV 宿主与工程闭环：选此项。它解决有代码/无发布具体入口的接缝，不自建Agent循环、通用评估平台或自动生成标准。

## 第一项具体交付

把既有两模块提升至 Runtime 源码，保留全部隔离、字节、超时、输入/输出/源码/模型/合同绑定及清理语义，公开原有普通/研究/五案例组合工厂和必要配置类型。旧 scripts 路径薄转发到同一实现，避免长期两份逻辑；旧真实尝试的源码身份以Git历史及独立原字节存档保留，不重跑、不回填旧证明。

源归属为：
- `packages/tianwen-runtime-bundle/src/isolated-python-cli.ts`：现有有界执行器和JSON结果比较；不增加宿主权限。
- `packages/tianwen-runtime-bundle/src/conversation-isolated-python-check.ts`：现有普通及研究结果生产者；使用包内模块与现有 evolution 包。
- `packages/tianwen-runtime-bundle/src/index.ts`：公开工厂/配置类型，复用现有 index.js/index.d.ts 构建，不增加安装依赖。
- 原两 scripts 文件：兼容转发；所有后续实验与包消费者共享实现。

公开适配器要求可信宿主事前提供原任务合同、独立输入/期望及精确环境配置，默认不启用。它不从模型答案推导标准，不为任意开放任务自动创造验证器。普通和研究调用保持 `ConversationExternalCodeCheck` / `ConversationStudyResultCheck` 原接口。

已知迁移风险是 `import.meta.url` 绑定：脚本实现原来以自己文件为 checker/executor 身份；打包后应绑定实际发行模块字节，必须在答案前准备并在执行时核对同一身份。不得把旧源码hash伪装成新发布物hash；旧结果不重判。

## 独立于第一项的后续工作

第一项交付后，使用真正的公开包消费入口核验 DEV 接线，先工程夹具、后适用实际待办。受控闭环应逐项检查研究拒绝/接受、治理、撤回、未来任务的准确方法版本和退化恢复；存在的机制直接复用，只修复实际暴露的缺口。隔离开启的产品不能把受控接受写成已激活；需要测试激活时必须使用单独明确隔离的工程夹具及现有测试配置，不改产品默认策略。

这不会自动提供自然效果证据。最终仍需真实任务/可归因反馈或问题、独立研究依据、有效方法、受治理采用、后续效果与必要回滚。开放文案的主体/因果/承诺/例外语义仍未解决，不能以Python案例通过冒充通用安全。此事实影响完整发布判断，不阻止第一项接缝实现。

## 本项完成判据与边界

只有发布清单中的实际 JS/声明可以导入具体工厂，工作区 scripts 薄转发与包消费者走同一实现；原有检查机制正反例、必要类型/构建和取消清理通过，才算第一项工程交付。没有模型调用要求、不重跑51案例及任何旧任务，不把包消费测试当自然收益，不新增全目标验收门槛。

main/Daily 完整学习NO-GO、有效同意、激活隔离、原发布要求、原十工作日窗口保持。复用D盘工作区与依赖；只保留必要日志/原字节/hash，不全量复制环境。目标不能因第一项交付被complete，也不能继续以“没有新自然失败”为由机械封死此项独立开发。
