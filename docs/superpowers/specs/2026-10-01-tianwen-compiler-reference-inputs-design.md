# 编译检查的显式只读参考输入

## 依据、目标及授权

继承所有者自主选择/持续实施授权、完整目标、原发布门槛与十工作日窗口。当前 e937e26 的具体 TypeScript producer 始终只准备 target 一项输入；正式 external-check 的 candidate 又要求完整 captured entries 摘要与准备一致。正常读取目标加参考文件的开发任务因此无法核验，不能把“输入更多”当候选代码失败。旧单目标合同有明确测试，不直接扩大默认域。

取舍：放松完整输入绑定会失去原前像保护；把所有编译依赖变成必读输入会给普通任务添加不合理要求。选择显式可选 `referencePaths`：可信宿主在原任务前声明实际需要读取的参考文件，默认无参考。它们独立于 contextPaths 的编译 root，允许普通说明文件，不改编译语义或输出范围。

## 行为

最多七项合法、互不重叠的相对参考路径，加 target 沿用普通文件捕获的八文件/每项98304、合计131072 UTF-8字节边界；不是生成案例的32768预算。配置在 factory 捕获；路径与读取复用普通文件工具的原规则，参考须确实存在且 UTF-8 可读，不创建/运行任何内容。声明格式/重复目标/别名/越界配置拒绝；缺失/非文件/过限读取不准备检查；无参考保留原行为。

prepare 在答案前捕获声明参考字节，与编译观察和 target 前像共同冻结；referencePaths 非空才扩展合同域，inputs 包含 target 和参考。evaluate 对完整输入使用共享规范摘要，允许读取顺序改变，丢失/额外/改字节都不可核验，不附失败条件摘要。运行时 outputs 是完整最终 entries；核对其路径集合和参考最终字节，选出 target，outputPaths 只能 target。参考丢失/变化/额外路径都不可核验，不扩展多输出修改权限。

参考在冻结后发生宿主磁盘变化不重读；若实际原生读到变化则捕获材料摘要不一致，不能出具合格失败。真实 compiler 失败的原 opt-in 摘要、宿主 options guard、项目约束/抑制/未知依赖/取消保持。参考字节不是事实语义自证，也不证明参考内容被正确使用。

## 正常、反例、失败与验证

正常故事：原任务读取说明和目标，只修目标；完整原生捕获包含两输入/一输出，编译verified，冷恢复准确且0模型。反例：没有显式参考的旧任务仍只接受原 target 输入，不自动借未声明文件扩权。失败故事：声明参考缺失或读取后漂移，不把宿主/捕获错误当条件失败。

先加真实 compiler 及完整原生 read-reference→read-target→write-target 红测试，再实现薄适配。覆盖默认/空参考、配置冻结、顺序、完整字节及路径/数量/类型、缺失/非文件/超限、只读输出、实际编译归属、冷恢复。相关回归、八包类型/实际bundle、全部修改TS基线及独立只读审查后推开发分支。
