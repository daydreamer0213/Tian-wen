# 有界假设探索：普通摘要能力的下一切片

日期：2026-09-05。状态：已在本地未提交检查点实现并通过脚本机制验证；尚未提交、集成、安装或发布。

## 已确认的目标与实际缺口

沿用持续学习治理设计第 6 节：已有证据足够就经验归纳；原因不明时才提出可区分假设，临时实验取得新证据，再归纳。当前 `LearningCase` 固定为 `experience-consolidation / experimentLimit: 0`，原生分析工具只有 `no-case / insufficient-evidence / skill-change`。因此“会生成 hypothesis 文本”不能算实现了探索循环。

本切片只扩展已接通的 `research-summary` Outcome 学习。输入仍是授权后冻结的两个失败任务和一个成功反例；不抓取更多会话，不扩大外部权限，不新增模型评委。明确纠正路径、旧记录及不需要实验的分析不改变。

## 三种方案与选择

1. 默认等待更多普通任务：零额外执行，适用于暂时没有可区分假设，但不能替代已批准的受控探索能力。
2. 在原分析中按需发起一次临时绑定对照：复用原生 child、Skill、产品工具、Run/Evidence 和既有学习流程。选择这一窄方案。
3. 所有分析都附加实验，或建设通用实验调度器：重复已有候选评测、增加正常路径延迟，没有当前需求，排除。

一次实验包含一对同条件的原始绑定/临时绑定 Runs。它是第一次切片的有限实验安排，不是给普通 DSH Agent 设置模型请求数或 token 额度。实验只回答提出时冻结的区分问题；不能从两次输出推出统计意义上的普遍因果规律。

## 正常产品流程

1. 已有证据可归因：原分析直接提交原有结论，额外实验数为零。
2. 值得进一步调查但原因未定：同一个分析 child 提交一个具体假设、一个竞争解释、要临时改变的任务指示，以及两种解释分别预期看到什么。必须引用冻结来源中的一个失败 Run，不允许模型自造新来源、修改验收标准或填入预期答案。
3. 在任何实验模型执行前保存不可变实验意图：analysis/Ticket、来源 Run、父 Skill、原 packet 摘要、当前模型设置摘要、假设、竞争解释、临时指示、观察口径、两个确定性子 Session 身份。重复同一请求复用意图，不再产生第二对 Runs；不同请求在当前实验未收口时不被接受。
4. DSH 原生子代理执行两个临时 Runs。两者采用完全相同的父 Skill、packet、模型设置、工具、只读能力和验收标准；唯一声明差异是 treatment 的临时任务指示。它不改 Skill 内容或活动指针，不进入普通 Outcome 复发计数。
5. 接纳正式产品工具返回，并从同一持久 Session 投影 Evidence、Outcome、实际 Skill 使用和实验绑定。沿用确定性检查器，将结果绑定到精确 `acceptanceEvidenceId` 后以 attestation 传入 `consumeOutcome()`；不能使用“工具调用成功”的默认值冒充任务 `met`。无输出或基础设施失败为 `inconclusive`，不当作假设被否定。
6. 将这两份有界观察返回原分析 child。它可以据此经验归纳、记录“本次观察不支持该假设”并保留反证，或保持证据不足；不另建模型裁判，不为获得好看结果改题重跑。单次配对无法排除模型采样波动。
7. 只有合法 `skill-change` 才进入现有 Candidate 比较、未见样本检查与采用链。实验结果不是 Candidate PASS，不消耗或暴露正式 holdout，也不改变已经运行的主 Session。

## 所有权和复用

- DSH：原生 child descriptor、权限继承、Session 持久化、Skill registry/loader、模型执行与继续。
- Tianwen：实验意图的冻结、两个实验 Run 与学习来源的关系、观察事实引用、分析回流与候选不能提前采用的边界。
- 已有 `bindRunWithSkill(..., 'exact-skill')`、`recordSkillUse()`、`consumeOutcome()` 和 `createResearchSummaryTool()` 可复用；实验 Outcome 使用 task-local 合同，避免作为新的普通失败循环触发自己。
- 当前大文件中 private 的候选执行方法要求 Candidate/evaluation 身份，不能通过伪造 Candidate 来复用。薄实验适配必须调用公共 DSH 能力和上述已有事实接口，不复制整个受控评测器，也不把私有 arm 方法改造成通用 Runtime。

## 停止与恢复

实验属于原有分析，不设第二个持久任务队列。先核对已持久的实验意图、子代理和收据，再决定继续尚未完成的工作。已完成 arm 不重跑；只有打开主会话不执行，用户发“继续”或原生恢复后沿用原来的子 Session。已有基础设施失败保留事实，不能隐式重置成新的正式尝试。

一个有限实验结束后必须回到归因。若两种解释得到相同预期、观察不能区分原因、来源不可用、权限前提失效或结果仍不充分，保留不足/反证并停止当前探索，不继续自动制造实验。阶段中的一次配对安排可在后续真实需求证明不足时调整，但不在本切片实现通用预算器、候选锦标赛或循环重试框架。

进度由同一主会话接收：正在核查原因 → 已取得观察/未能核查 → 原学习结论。不给用户新增实验批准按钮；若任务需要当前边界之外的权限，仍只通过主会话处理原生 DSH 权限。

## 可反驳的验收

- 充分证据与 no-case 分支：实验数必须为零。
- 请求晚于最终结论、重复变更意图、跨分析来源或父版本：不能产生实验执行。
- 脚本模型只提供输出，原生子代理/产品工具/证据投影完整走通一对实验；当观察相同，允许不足结束且零 Candidate。
- 有区分观察可以回到原分析产生一个受治理 Candidate；实验完成本身不能切指针。
- 中断后仅打开主会话不调用模型；主会话继续复用已完成 arm 和原未完成 child。
- 不为这一阶段额外制造真实模型失败。真实效果应来自一个本来就值得解决的问题；没有该问题时保留机制证据分类。

## 分段交付

A. 不可变实验意图与观察事实合同；B. DSH 原生临时绑定执行和收据；C. 原分析的按需工具、回流、主会话恢复与进度。三个切片完成前，不能宣称“探索学习已实现”。现有经验归纳路径在各切片期间仍可独立工作。
