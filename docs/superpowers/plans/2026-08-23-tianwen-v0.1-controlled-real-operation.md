   label；不复制 raw material。
6. **stop：** 每一阶段插入 Provider/tool/persistence/identity/workspace/root/pointer fault，证明首个
   failure 后无下一 Agent/请求，且不 continuation partial activity。

- 25 个 Session 都来自实际 DSH Agent 并 durable；

- ordinary root Skill、legacy Champion、其他 controlled scope、real product root untouched；

### 9A4-R6 修正 parent monitor 的 Node 进程/流收尾语义

- R5 唯一一次 outer official installed Tianwen CLI 诊断仍在 15 秒后以 `ETIMEDOUT` 停止，stdout/stderr
  均为空，且没有 Session 或 Evolution ledger。R4 对同一 official install、DSH bin、Profile、patch、
  manifest、测试凭据和 loopback Provider 隔离的 direct child 已在 15 秒内正常退出并返回经既有 parser
  验证的 `selection-mismatch` receipt。只读逐字段对照没有发现 executable、argv、environment、cwd、
  DSH identity 或 patch identity 的语义差异；当前唯一新增语义层是 Tianwen 自建的、无限等待 child
  `close` 才解析回执的 parent monitor。
- 这是 official `tianwen controlled-lifecycle` 入口的真实可用性 blocker，但范围只到 child transport；
  不得再检查或修改 installer archive、runner、loader、评测 reducer、Agent loop、Provider、Session/
  Evolution ownership。R4/R5 已足以排除这些方向，不得用新的长 E2E 反复碰运气。
- 保留异步 `spawn()`：正式 lifecycle 是长运行前台命令，仍需正常的事件循环与取消/信号语义，不改成
  `spawnSync()`，也不新增 dependency。问题在收尾条件，不在异步启动本身。
- Node 的 child `close` 不只代表 OS child 已退出；它还等待 stdout/stderr 的底层 pipe socket 都完成
  `close`。当前实现因此把业务完成额外绑定到 Windows pipe teardown。最小修正为分别记录 child `exit`、
  stdout `end`、stderr `end`，三项齐全后才按现有 parser 与 exit-code 合同 finalize；不再以 child
  `close` 作为唯一完成信号，也绝不能仅在 `exit` 时提前解析尚未读完的输出。
- 保留现有 exact executable/argv/env、`shell=false`、pipe、64 KiB 上限和 safe failure；spawn/stream error、
  signal、overflow、非法/多行 stdout、任何 stderr、digest 不匹配或 receipt/status 不一致都继续 fail
  closed。合法结果仍经 `parseControlledLifecycleChildReceipt()` 验证并重新序列化，不直接转发
  child-controlled bytes。完成后只做局部 listener/stream 释放，不建设通用 child-transport 框架。
- 先在 `controlled-lifecycle-command.spec.ts` 建精确 RED：fake child 写合法 stopped receipt，随后
  stdout/stderr `end` 并 emit `exit(1)`，但故意永不 emit child `close`；当前 promise 必须被证明仍 pending，
  修正后应只转发一行并返回 1。再冻结乱序到达：exit 或两条 EOF 任一缺失时不能 finalize；EOF 前追加
  第二行或任意 stderr 仍 fail closed；正常 success/stopped、overflow 与 error 既有合同保持。
- 不添加整段 lifecycle timeout。若真实流连 `end` 都不产生，focused 诊断必须停止并回报，不能用 timer、
  kill 或 retry 掩盖；届时才有证据把问题升级为继承写端，而不是本轮已定位的 close-only 过度等待。
- focused GREEN 后，只允许一次不安装产品的 15 秒短诊断：复用 preserved official install 与 R4 完全
  相同的 child invocation，通过修正后的 async monitor 执行；只记录安全计数与 parser verdict，仍用
  development-only credential 和 loopback Provider 隔离。若得到合法 `selection-mismatch`，即闭合修复；
  若失败立即停止，不再增加诊断框架或尝试其他 transport。
- 不再运行十分钟级 official installed E2E。永久保留 post-R3 首次 outer timeout 和 R5 复现；Task 9A4
  以 official installer/archive 已通过、installed publication 合同、R4 direct child、R6 corrected
  transport 短诊断及 focused/compatibility gates 收口。第三个 official non-fresh Session 子例只声明
  focused contract 覆盖，不冒充同轮 official installed proof。最终真实 official CLI 证明由 exact-main
  CI 后本来就只运行一次的 Task 9B official install + controlled command 提供，失败仍按 Task 9B 停止线
  保留，不重试。
- R6 不新增 timeout、retry、telemetry、stage marker、lifecycle framework、预算器或 dependency；实现仍限
  Task 9A4 已授权文件，commit 仍为 `feat: publish controlled lifecycle runner`。

### 9A4-R6 复审闭合：异常 child 回收、fresh state owner 与长门授权

- R6 的正常 transport 已由精确 RED、focused GREEN 和 preserved-install 短诊断证明：child `exit`、
  stdout `end`、stderr `end` 三项齐全后可在约 4.9 秒内返回合法 `selection-mismatch` receipt；不再
  重写为 `Promise.all`、async iterator 或另一套 transport framework。复审只剩三项当前可达缺口，
  必须在 Task 9A4 提交前用最小改动闭合。
- **异常 transport 必须收回 child：** 当前 `fail()` 在 stream error 或 close-before-end 时先返回并移除
  listener，却没有终止尚未 exit 的 DSH child；这会让 Agent/Provider/tool 仍可能继续运行，也可能让
  child handle 继续拖住 outer CLI。先扩充现有 focused test：child/stream error、stdout/stderr
  close-before-end 与 overflow 均应返回同一有限错误；若尚未观察到 `exit`，`kill()` 必须恰好一次；随后
  再触发第二个 error/close/end 不得抛出、不得第二次 kill、不得第二次输出。合法 success/stopped 为
  `kill=0`；已经观察到 exit 后才发现 receipt/status 非法也不再多 kill。
- GREEN 只保留现有显式三事实状态机，增加一个局部、幂等的 termination 标记。首个 transport failure
  在 child 尚未 exit 时请求一次 kill 并关闭两条本地 pipe；overflow 复用同一路径，不单独再 kill。
  failure 状态继续吸收随后的 stream/child error，不能因为过早 cleanup 制造未处理异常；成功路径仍按
  现有 cleanup。不得新增 timeout、retry、AbortController、通用 helper/module 或 dependency。
- **fresh state 的已存在 owner 必须仍归产品所有：** `sessionsRoot` / `evolutionRoot` 本身不存在可以是
  合法 fresh 状态，但固定相对链上任何已经存在的目录段都必须是普通目录、不是 symlink/junction，且
  `realpath` 仍在 canonical `dataDir` 内。先增加 `dataDir\\state` 是指向外部目录的 junction、
  `state\\evolution` 尚不存在的 RED；parent preflight 必须在 0 child 停止，外部目录仍为 0 files。
  GREEN 只检查这两条固定 owner 链，不建设通用路径策略或状态根框架。
- **十分钟 official installed E2E 改为显式授权门：** 当前测试只按 Windows 判断，会让普通
  `pnpm run check` 自动运行 installer。增加窄开关 `TIANWEN_CONTROLLED_INSTALLED_E2E=1`，且必须同时
  为 Windows 才运行；默认 targeted invocation 应显示 skip，并且不创建 installer/product 现场。本轮
  不设置该开关、不重跑长 E2E。Task 9B 获得真实操作授权后仍走其独立的一次 official install +
  controlled command，不复用这项 development E2E 冒充正式证据。
- TDD 顺序固定为：先只改 command spec 得到 transport failure 与 state-parent junction RED，再做最小
  产品 GREEN；startup E2E 的 `runIf` 授权条件属于测试执行边界，直接做一处窄配置修正，并以未设置开关
  的定向 invocation 证明整项被 skip、没有 installer 现场。随后 fresh 运行
  `controlled-lifecycle-command.spec.ts`、默认禁用的 startup 定向节点、Task 9A4 固定四 spec、Runtime
  Bundle recursive build、全仓 typecheck、no-private-imports 和 `git diff --check`。R6 preserved-install
