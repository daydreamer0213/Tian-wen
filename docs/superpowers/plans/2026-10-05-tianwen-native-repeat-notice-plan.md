# Native SDK Repeat Notice Compatibility Plan

**Goal:** 原生结构化判断正确处理 SDK 已验证的辅助提醒，结束已明确判错却因运行消息格式被拒收的流程错误。

**Scope:** `conversation-judgment.ts` 的共享恢复函数与现有判断测试；不修改原判据、源码事实、历史结果、驱动、研究次数或发布门槛。所有者已批准主动模拟全部缺失条件，沿既有执行/TDD/发布验证流程，不再请求已授权确认。

- [x] 原唯一真实批首结果、生产只读恢复拒绝位置和 SDK 默认提醒协议核实，原错误/轨迹保存，Docker自停及准确重复清理。
- [x] 先写模拟原SDK提醒的RED，固定原工具错误修正后唯一成功捕获；覆盖3/5/8支持的提醒、原捕获提醒共存和公共共享判断入口。
- [x] 最小实现：核SDK source/form/summary/text、原同参数连续实际工具调用/结果及顺序，提醒仅作为运行辅助；原用户请求/材料/摘要/lineage/capture/引用语义检查保持。无来源/伪计数/变文本/未知插件拒绝。
- [x] 源码/严格类型/原构建/发布检查，公共 SDK 真实触发提醒并恢复原判断的零模型控制，限定只读复查。原无效结果不补评。
- [ ] 提交推送当前隔离分支，按原固定阶段用新任务身份继续受控研究/未来/撤回；反馈缺条件也自行模拟，保持来源透明，所有缺陷修复由执行者负责。

**Acceptance:** 合法SDK提醒不再使已捕获的真实评审无法恢复；不凭提醒或负面评分新增事实或学习结论。已有受控阶段用独立结果验收，缺自然样本不是开发停止理由。
