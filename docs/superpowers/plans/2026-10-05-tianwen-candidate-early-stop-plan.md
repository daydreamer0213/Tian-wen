# 候选失败提前停止与整批超时

继承用户主动构造条件、自主持续推进授权。完整目标保持 active；不新增 main/Daily 发布门槛，不补判旧研究。

实际 r6 的第一候选说明错误，但仍继续到反例评审，86 次真实请求后 invalid-judgment 停止。操作员重复恢复已在线 root 报错，清除了前台计时器；后台原 Loop 使用独立 controller，原45分钟预算失效。这两个问题由实现和操作员负责，不需要用户提供题目或批准。

选择最小修复：保存原双评审与功能检查完整臂，再对未完成研究追加有据的 `candidate-failed` stop。现有两种裁决均要求所有候选通过，所以已有候选 not-met 或功能 rejected 后，剩余案例不能恢复资格。未知/inconclusive 不按失败提前停止；完整十臂沿原裁决。相比继续跑完，提前停止节省请求；相比制造部分 rejected 裁决，stop 准确保留未完成事实。

新增停止原因须原账本验证已有候选失败且案例不完整；支持冷恢复、禁止后续写入与启用。旧格式、旧停止、十臂门槛、原功能条件保持。状态统计单列 candidateFailed。

操作员整批计时器在原 DEV runtime 加载前安装，绑定原 ctx 生命周期，阶段 finally 不得清除。超时取消操作员 signal 并调用原 `appExit(1)`，由原生命周期结束独立 Loop。原 CLI 仍只有5秒关闭预算，不声称无限等待；不使用 Windows process.kill 或虚假的 one-shot interrupt。
