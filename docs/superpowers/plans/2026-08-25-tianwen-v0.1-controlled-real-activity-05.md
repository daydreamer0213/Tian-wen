# Tianwen v0.1 Controlled Real Activity-05 Execution Plan

> Execute continuously through the next safe checkpoint. Do not request repeated approval. Stop only
> for an authority conflict, a non-recoverable product result or a real Provider action not covered by
> the approved design.

**Goal:** Run one fresh official controlled lifecycle against the verifier-verdict ownership repair.

**Architecture:** Install the reviewed main into a new product root, freeze the existing task material
under new Activity-05 workspace/Session identity, invoke the official product once, and accept the
first terminal lifecycle result.

**Authority:**
`docs/superpowers/specs/2026-08-25-tianwen-v0.1-controlled-real-activity-05-design.md`

## Global constraints

1. Activity-01 through Activity-04 are immutable and are never replayed or used as live state.
2. Product, evidence and operation roots are new and must be absent before their owner creates them.
3. Large caches remain under `D:\DevData`.
4. Official product commands use the installed `.CMD`, PowerShell call operator, tokenized arguments
   and no shell-built command string.
5. The configured credential reference may be inherited; its value is never read or printed.
6. Do not set a loopback or test Provider URL.
7. No command is retried after the official target begins.
8. Offline recovery runs once after setup failure or any lifecycle result.
9. No checker, postmortem, probe, smoke, dry-run or Goal.

## Task 0: Authority takeover

1. Confirm clean exact main and matching `origin/main`/remote main.
2. Confirm automatic push attempt 1 for that exact main has Python, TypeScript and
   installer-windows successful.
3. Read the Activity-05 design/plan/packet and the four bound Git authority objects.
4. Confirm the new product, evidence and operation roots do not exist.
5. Stop on any mismatch; otherwise continue directly.

## Task 5: Execute exactly one formal lifecycle

Predeclare separate exclusive stdout/stderr/exit targets for all six occurrences:

```text
1. model status --data-dir <productRoot> --json
2. model use --model deepseek-v4-pro --data-dir <productRoot> --json
3. model status --data-dir <productRoot> --json
4. controlled-lifecycle --manifest <manifestPath> --data-dir <productRoot> --json
5. model use --model offline --data-dir <productRoot> --json
6. model status --data-dir <productRoot> --json
```

The readiness status in Task 3 is occurrence 1 and is not repeated. Execute occurrences 2-6 as
follows:

1. DeepSeek model use once. Require exit 0, empty stderr, valid receipt, exact selection, configured
   credential and zero request delta.
2. DeepSeek status once with the same requirements.
3. Invoke controlled-lifecycle exactly once. This consumes Activity-05.
4. Accept the first valid passed/stopped receipt or terminal transport failure. Never replay it.
5. Run offline use once and final status once even after a stopped/transport-failed lifecycle, unless
   the launcher itself is unavailable.
6. Require final offline selection and zero request delta.

For a passed receipt, verify 25/25 roles, D1/D2, Ticket, evaluation, Shadow, three transitions and
the final pointer. For any other result, report the receipt plus already-durable Session/Evolution
facts without inventing missing counters.
