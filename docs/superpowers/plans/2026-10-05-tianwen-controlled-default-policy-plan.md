# 受控默认策略故障实现计划

**Goal:** 主动构造可修复的默认输出/报告规则错误，由实际模型提出方法并检查后续任务是否改善，不等待自然样本。

**Architecture:** 沿原DEV工厂、Native Goal/Task、独立结果、研究和治理接缝。故障仅在D上的操作员实际请求投影；完整原caller合同保持可读，普通和两研究臂使用同样故障。先检查场景能否触发实际错误，再投入原完整受控流程；候选和答案不手写。

**约束与选择：** 上一批四基线2/4、三训练3/3，所以没有研究问题；这是场景准备责任，不是产品blocked。可模拟旧默认渲染策略或错误的完成报告模板，均保留正确原要求。有限独立设计复核指出：method-only优先级例外会混入“方法存在即可获得纠正许可”，不宜作为泛化改善证据；选择行为条件，两臂都可从同一原caller合同辨识并覆盖错误默认，不要求终答附解释。若实际效果只证明人工默认修复，按该范围报告。
