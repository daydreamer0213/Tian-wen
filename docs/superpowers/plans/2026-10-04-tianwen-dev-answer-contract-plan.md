# 标准 DEV 入口消费已有答案检查器

基线 eef7652c。完整目标 active/incomplete，main/Daily NO-GO。原资格、五案例十臂、双审、语义和十工作日决策窗口不变。

## 已确认缺口和范围

公开 Python 答案检查工厂与 Loop 的 text/file-chat 事前供给已交付；标准 DEV JSON 插件只向 Runtime 传入 code/files 的 studyResultCheck。正常 Loader 因而无法从已锁定的可信数据装配 answerStudyResultCheck。补已有适配器的可选 answerStudyContracts，不另建执行器、Agent、平台或结果库。

合同使用原工厂的 modelConfigDigest/cases/provideIndependentCases，不接收 isolated、命令、插件或 Runtime 开关。沿用原已验证 Python 镜像及隔离执行器，固定生成物 D 目录。文件 chat 合同须属于原冻结 workspace；所有合同数据在不可写的外部路径按原 SHA-256 验证。加载只构造，不准备环境、启动 Docker、请求模型或授予同意。缺省保持原行为。此接口仅检查显式案例，不承担开放语义 oracle。

## 执行和收口

1. 红测：原固定合同无法加载；原 Loader 安装后的 Loop 缺少答案供给。
2. 薄接入；验证缺省兼容、完整副本、材料/模型漂移拒绝、跨 workspace/执行配置拒绝。
3. 原正常 Loader 实际导入发行工厂及 Runtime，核验供给确实传到 Loop；0模型、0环境准备、0学习事件。已有实际工厂执行证据不重复。
4. 独立审查和适当相关回归；提交并更新当前交接。历史账本只读，测试自有根清理，D>=15GiB，77保护根不碰。

该交付不制造自然问题、用户反馈、研究成功或未来收益。接线收口后下一工作仍是事前固定真实项目待办及可复用的独立依据，在冻结执行版本上唯一首次执行；自然来源未形成时记录没有触发，不能追加零散小题凑来源。
