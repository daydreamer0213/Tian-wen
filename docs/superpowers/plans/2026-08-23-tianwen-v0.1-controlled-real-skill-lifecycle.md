## Task 2B：冻结 blind map、记录 evaluator observation 与双层 result

**允许文件：** 与 Task 2A 相同。

### 产品 service 闭环

Task 2B 结束时，Task 3 需要的整个 controlled-evaluation ledger 表面必须可通过
`ctx.tianwenEvolution` 到达；Task 3 不再修改 Evolution。除 Task 2A 已补齐的 objective 三个
方法外，在 `runtime-binding.ts` 只增加同名 typed forwarding，不增加 adapter 或第二状态：

- 既有 protocol：`freezeControlledSkillEvalProtocol(input)`、
  `getControlledSkillEvalProtocol(protocolId)`、`listControlledSkillEvalProtocols()`；
- 既有 plan：`openControlledSkillEvaluation(input)`、
  `getControlledSkillEvaluation(evaluationId)`、`listControlledSkillEvaluations()`；
- 本 Task 的 blind map、evaluator observation 和 result 六个 API。

所有 write 继续经过现有 `formalWrite`，read 直接读取同一个 ledger。focused test 必须固定这些
产品入口存在且类型与 `EvolutionLedger` 同名方法一致，避免“账本会做、真实 Runtime 调不到”。

### 新事件

- `controlled-skill-evaluation-blind-map-frozen`
- `controlled-skill-evaluator-observation-recorded`
- `controlled-skill-evaluation-result-recorded`

全部使用同一 ledger 管线并保持 private；不得建立 evaluator database 或第二 state machine。

API 名固定为 `freezeControlledSkillEvaluationBlindMap({ evaluationId })`、
`getControlledSkillEvaluationBlindMap(evaluationId)`、
`recordControlledSkillEvaluatorObservation(input)`、
`listControlledSkillEvaluatorObservations(evaluationId)`、
`recordControlledSkillEvaluationResult({ evaluationId })` 和
`getControlledSkillEvaluationResult(evaluationId)`；write receipt 分别只含自身 identity 与
`duplicate`，不返回 caller-authored decision。

三个 record/event schema version 分别固定为
`tianwen.controlled-skill-evaluation-blind-map.v2`、
`tianwen.controlled-skill-evaluator-observation.v2`、
`tianwen.controlled-skill-evaluation-result.v2`。blind map/result write receipt exact 为
`{ evaluationId, duplicate }`，observation receipt exact 为
`{ evaluationId, taskId, duplicate }`。exact duplicate 必须先于 terminal-state 拒绝返回
`duplicate=true`，conflicting duplicate 一律拒绝，供 commit-unknown 恢复使用。

### objective aggregate gate

- Candidate objective `not-met` 时，result 可立即归约为
  `rejected/candidate-objective-hard-gate-failed`；Candidate objective `inconclusive` 时可立即
  归约为 `inconclusive/objective-inconclusive`。baseline inconclusive 且 Candidate 未失败时
  同样归约为 `inconclusive/objective-inconclusive`。此时 blind map 必须不存在。
- 五个 Candidate objective 全部 `met` 后，T1/T2 至少一项必须 `candidate-better`；否则
  result=`rejected/original-or-adjacent-not-improved`，不运行 evaluator。
- 只有 objective aggregate=`pass` 才能冻结 blind map。

### blind map exact derivation

- `objectiveSetDigest = sha256(按 protocol 顺序的五个 immutable objective records)`。
- 每 task 的 assignment bit 为
  `sha256({ domain: 'tianwen.controlled-blind-map.v1', evaluationId,
  objectiveSetDigest, taskId })` 最后一个 hex digit modulo 2；0 表示 X=baseline，1 表示
  X=candidate，Y 永远互补。调用方只提交 evaluationId，不能提交 mapping/seed。
- 每个 private assignment 保存 taskId、xRole/yRole、plan evaluatorSessionId 和
  envelopeDigest。envelopeDigest 绑定
  `tianwen.controlled-blind-envelope.v1`、taskId、rubricDigest，以及 X/Y 各自的
  evaluatorMaterialDigest、outcome、`sha256(evidenceIds)`；不含 B/C 或其他被禁止身份。
- blind-map record exact 为
  `{ schemaVersion, evaluationId, objectiveSetDigest, assignments }`；assignments 必须按 protocol
  task 顺序，每项 exact 为
  `{ taskId, xRole, yRole, evaluatorSessionId, envelopeDigest }`。`xRole/yRole` 只能是互补的
  `baseline|candidate`。`blindMapDigest = sha256(blindMapRecord)`。

### evaluator observation

- common exact keys：`evaluationId, taskId, evaluatorSessionId, envelopeDigest,
  requestDigest, evidenceId, status, insufficientMaterial, reasonCode`。
- `status=scored` 时 `insufficientMaterial=false`、reasonCode=`score-submitted`，并额外含
  `scores`；scores exact 为 x/y 两组，每组只有
  `relevance, correctnessReasoning, clarityUsability, scopeRestraint` 四个 0–4 整数。
- `status=inconclusive` 时 `insufficientMaterial=true`、不得含 scores，reasonCode 只能是
  `material-missing | identity-exposed | objective-facts-incomplete | provider-failed |
  timeout | score-not-submitted`。
- observation 严格按 protocol task 顺序，每 task 一份；exact duplicate idempotent，冲突
  或 second submit 拒绝。第一份 inconclusive 后拒绝下一 evaluator observation。
- 持久化 observation 在 caller union 上只增加上述 observation schemaVersion，不增加 prose、
  identity reveal 或控制器代填字段。`evaluatorSetDigest = sha256(按 protocol 顺序的全部已持久化
  observation records)`；因此 evaluator 已开始但提前 inconclusive 时保存 partial-set digest，
  evaluator 阶段完全未进入时才为 `null`。

### result pure reducer

- public input 只能是 `{ evaluationId }`；调用方不能提交 verdict、score total、reason 或
  evidence claim。
- 固定字段：planDigest、objectiveSetDigest、blindMapDigest/evaluatorSetDigest（不适用时
  `null`）、mechanismVerdict、evidenceClaim、naturalUserEvidence、shadowEligibility、
  按 reducer 优先级唯一确定的 reasonCode、baselineTotal/candidateTotal（未评分时 `null`）。
- result record exact keys 为
  `{ schemaVersion, evaluationId, planDigest, objectiveSetDigest, blindMapDigest,
  evaluatorSetDigest, mechanismVerdict, evidenceClaim, naturalUserEvidence,
  shadowEligibility, reasonCode, baselineTotal, candidateTotal }`。`planDigest=sha256(plan)`；只有
  五个 objective 齐全时 objectiveSetDigest 才为 ordered-set digest，否则为 `null`；blind map
  未冻结时 blindMapDigest=`null`；evaluator 完全未进入时 evaluatorSetDigest=`null`。只有五份
  scored observation 齐全时 totals 为 0–80 整数，否则两者同时为 `null`。
- `naturalUserEvidence` 在 v0.1 固定 `not-claimed`。evidenceClaim 由 evidencePurpose 唯一映射；
  pass synthetic → `eligible-for-isolated-test-shadow`，pass controlled-product →
  `eligible-for-project-shadow`，其他 → `ineligible`。
- `mechanismVerdict` 只允许 `pass|rejected|inconclusive`；`evidenceClaim` 只允许
  `controlled-product|controlled-synthetic-mechanism`；`shadowEligibility` 只允许
  `eligible-for-project-shadow|eligible-for-isolated-test-shadow|ineligible`。result reasonCode
  只允许七级 reducer 产生的固定原因，或第 4 级透传 observation 的六个 inconclusive 原因；
  任何 caller-authored verdict/reason/total 均作为 unexpected field 拒绝。
- reducer 严格使用 canonical design 4.9 的七级优先级；subjective total 分别对每个 arm 的
  五 task × 四维共 20 个分数求和（各 0–80），单维回归按同一 task/同一维度的
  C-B <= -2 判断。
- prerequisite 不完整时 method 拒绝 `evaluation incomplete`，不持久化假结论。
- 如果最后一个 objective 已是 rejected/inconclusive，result 可立即记录；五个 objective 全部
  pass 但 T1/T2 无改善时也可立即记录。其余路径缺 blind map、缺当前顺序 observation，或只
  有部分 scored observation 时均是 incomplete。result durable 后不得写新 map/observation；
  已存在记录的 exact duplicate 仍可幂等返回。
- 覆盖 objective early reject/inconclusive/no-improvement、五 score pass、总分较低、任一维
  低 2、evaluator 各种 inconclusive、duplicate/conflict、replay/privacy。
