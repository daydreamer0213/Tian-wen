# 新状态汇报任务的自动学习验证

继承用户主动设计任务、环境与失败的授权，完整目标 active。此前过期索引两个实际程序任务功能满分，保留原结果而停止该批；这里是不同的新任务，不重判或改造旧样本。

## 任务与可比较结果

设计八个有不同项目、数量和时间的状态汇报任务。每个包含旧缓存摘要、原始检查结果、较新撤回记录和独立发布决定；用户要求自然易懂的当前汇报，不执行发布。来源及权威范围事前明确：缓存不是新检查结果，某个方法停用不等于任务从未完成，局部检查通过不等于项目发布，建议不是已批准行动。

两个训练源允许明确模拟的错误交付，模拟响应和真实请求分开记录；正常对照、原生入题、反馈归因（仅在实际提交反馈时）、案例设计、候选、研究评审和后续交付由原 SDK 完成。不能凭任务设计文件称已有学习证据，也不能由操作员手写候选或启用记录。

复用原 public applyDevelopment 和普通 text 任务入口，以 writing 或 summarization 的实际原生判断为准，不改 family 来配对。文本不要求代码功能检查，不把未配置的检查称 verified；事实/语义结果按原内容评审记录，并独立核对冻结的原始记录。研究仍沿原十臂与 dev-paired-any-case.v1，不新增正式发布条件。

先单独新 baseline profile 收集冻结未来任务的一次实际结果。原环境与模型配置在本批前后相同；不改配置或答案取得成功。基线全 met 时不声称改善、不重跑同批凑失败。研究有原实际接受才自动启用；未来任务用新 session，核方法实际注入与交付、原检查；撤回后再核无注入。任何停因保留首记录，只修实现或配置，不把不完整研究改为已完成。

## 执行与停止

- [ ] 在 D:/DevData 冻结八项新任务、显式模拟交付、逐项可核对事实；保存模型配置与旧证据摘要。只复用既有安装，零模型准备不算学习。
- [ ] 原 CLI 零调用预检；独立 baseline profile 一次实际未来交付。模型/时间/容量限制覆盖整个 ctx，退出用原 appExit，不强杀或重复恢复在线 root。
- [ ] 有实际比较空间后，正常对照与两训练源进入原研究；有失败候选按原 candidate-failed 保存后停止，原接受才自动激活。
- [ ] 新后续任务、实际方法注入、语义效果、撤回后的原任务与冷恢复逐项核验；模拟与真实结果明确区分。
- [ ] 原生命周期排空，核旧账本/消费者/环境，清理本批可再生残余，更新两权威记录。D 不低于15GiB，尽量20GiB，无依赖副本；main/Daily NO-GO/R9 保持。

此计划不能证明自动学习已经完成。原任务完成、反馈归因、研究裁决、自动启用、新任务改善及安全撤回分别缺什么就实现或主动设计什么，不向用户反复索题。
