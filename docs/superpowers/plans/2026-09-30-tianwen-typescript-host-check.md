## 设计与范围

新文件 scripts/conversation-typescript-check.ts，项目宿主通过 createConversationTypeScriptCheck 配置 cwd、requestText、targetPath、contextPaths、compilerOptions。它是明确配置的项目侧适配器，复用现有 TypeScript 6.0.3，不打包进 Daily 或缺省启用，不安装依赖。

prepare 仅适用于准确 cwd、原始请求文本、external/code 和配置的一项相对目标路径；目标/上下文必须在项目内。回答前克隆配置、固定目标原内容、编译器和检查器字节、选项，以及原编译期间实际读取的文件/缺失、目录、目录子项、真实路径观察。已有内容或 null 都可作为目标输入；新文件的基线编译用空模块，仅用于捕获检查依赖，不是预写候选。

evaluate 只能替换目标的完整候选；原输入、唯一输出路径与内容须匹配。使用新 CompilerHost，所有读操作只来自冻结观察；无当前磁盘补读、emit 或候选代码执行。新增未知依赖不可核验，已捕获依赖后续变动不能改变结果；类型错误拒收。取消在编译前后检查；现有 observer 仍负责候选/原生保存/取消竞速和最终结果绑定。

固定 strict/noEmit，拒绝新增屏蔽类型检查的指令；结果说明仅含检查范围、诊断数量/代码，不返回源代码或任意编译器错误全文。verified 只证明此冻结类型检查，不证明行为、用户原要求整体完成、研究资格或采用。保持当前 external 模型 review inconclusive、学习资格与新激活隔离。

## 候选前验收

1. 控制端先写不可由候选修改的机制检查，覆盖准确适用、输入/输出身份、类型正确/错误、依赖在准备后漂移、未知依赖、检查屏蔽、取消、无执行/emit，以及 existing observer 分开记录。
2. 固定这些测试和宿主接口、依赖源码身份，再运行一个原生文件实现任务，64K/high、提供者重试0、有界截止。模型仅写新目标文件，参考不可变；控制端不写或修补受评候选。
3. 冷恢复原生文件收据与 session，检查输出身份和范围。独立 TypeScript 检查仅核验类型；候选另外接受源码审查和冻结行为测试，不能用候选检查器评价自身。
4. 候选合格才原样采用；失败保存初次结果，不重跑求绿。机制问题可另行修复，但必须区分控制端工程修复与原生候选。
5. 受影响回归、严格类型、独立代码审查；更新当前交接与路线，保留完整目标 active、原门槛/十工作日窗口、main/Daily NO-GO。所有运行数据在 D:/DevData，小记录与必要原生证据保留，副本/test 根收尾检查。
