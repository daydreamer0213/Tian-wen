# 天问持续学习控制面收口研究

**日期：** 2026-08-12
**目的：** 对照前期讨论、上游源码审计与专业资料，收口首个持续学习垂直切片实施前仍未解决的设计问题。
**范围：** Harness 层持续学习，不包含模型权重训练；以本地单用户、Python、PydanticAI Harness、SQLite 为第一阶段约束。

## 1. 最终结论

天问的原始方向不需要推翻。真正需要补充的是一套“控制变化的控制面”：

```text
人类确认的 Goal 与不可变底线
→ 任务执行产生可核对事实
→ 事实进入受限学习队列
→ 形成案例、假设和能力候选
→ 定位应修改的最小层
→ 生成不可变 Challenger
→ 独立评测、影子或灰度
→ 晋升、限制适用范围、拒绝或回滚
→ 后续不同真实任务继续验证
```

这里的持续学习既能服务用户目标，也能服务“完善天问”元目标。二者不是两个不同体系，而是使用同一 Goal/Loop/Task/Run 协议、目标对象不同的循环。

第一阶段不应开放 Runtime、底线、权限、评测门槛和发布器的自我修改。元学习可以提出这些层面的改进建议，但不能用自己修改过的标准证明自己进步。

## 2. 与旧结论的关系

### 2.1 旧结论得到确认

- 顶层 Goal 和核心意图由人类掌握；
- Agent 遇到不可行目标时先报告证据并提出保留意图的替代方向；
- 用户目标循环与“完善天问”元目标循环并行存在；
- 每个大目标循环都可以派生多个有限子循环；
- 每个 Loop 内部都有任务执行循环和学习更新循环；
- 任务实践是最终证据，离线评测只是上线前预测；
- Champion/Challenger、保护评测、影子、灰度、回滚和版本冻结继续保留；
- 状态、权限、预算、事件和版本不能只存在于聊天上下文；
- 第一阶段使用 Python + PydanticAI Harness，不 Fork Hermes；
- 首个验证环境是本地 Git 仓库，首个且唯一可进化对象是 `repo_task` Skill；
- 模型权重训练延期到 Harness 学习链稳定以后。

### 2.2 旧表达需要修正

1. **“状态多就是完整”需要修正。**
   内部可以保存丰富事实，但模型每一步只接收少量局部选择。生命周期状态、等待原因、风险事实和评测结论应分字段保存，不能全部压成一个巨大枚举。

2. **“思路展示”需要改名。**
   用户需要的是由 Goal、动作、工具结果、实验和未知项生成的“证据化决策说明”，不是模型未经整理的内部思维文本。

3. **“每个事件都触发完整学习”需要修正。**
   所有执行都可以产生信号，但只有具有复用价值、阻塞价值、风险价值或明确用户反馈的信号才进入有限 Learning Job。

4. **“元循环读取用户循环”需要增加数据边界。**
   元循环不能默认读取原始对话、文件、命令、路径和工具输出，只读取经过用途检查、脱敏和字段白名单转换的证据视图。

5. **“评测也可以持续进化”需要增加独立治理。**
   评测可以被改进，但修改评测协议本身是独立工单；新协议必须与旧协议并行桥接，不能立即替换旧标准来证明当前候选更好。

### 2.3 本轮新增设计

- `Trajectory/Event → Case → Lesson → Artifact Candidate → Eval → Promotion` 的正式学习链；
- 先定位“最早有效分歧”，再选择最小修改层；
- 记忆写入防火墙、用途边界和派生数据血缘；
- 按版本与条件维护的能力账本，以及低成本能力探测；
- 元学习和评测修改的权限阶梯；
- 单机长期运行的租约、版本清单、幂等动作和崩溃对账；
- 证据化决策说明与低打扰介入门。

## 3. 模型判断复杂度：丰富事实，少量选择

复杂状态的主要风险不是数据库字段多，而是要求模型一次判断太多全局状态和转移。

推荐分工：

| 事项 | 负责者 |
|---|---|
| 状态是否合法、预算是否足够、权限是否允许、版本能否晋升 | 确定性程序 |
| 目标含义、未知项、失败假设、候选改进方向 | 模型 |
| 选择当前允许的下一类动作 | 模型从少量选项中选择 |
| 把选择转换成具体状态变化并验证前提 | 确定性程序 |

第一版 Run 继续只保留少量主状态：

```text
queued / running / waiting / completed / failed / cancelled
```

为什么等待、为什么失败、是否可重试、是否需要用户、哪个副作用未知，都使用独立原因字段。具体状态数量由契约测试和真实使用决定，不因架构图好看而扩张。

模型每一步只需要面对与当前位置相关的 3—5 个动作，例如：

```text
继续当前方案 / 做低成本探测 / 开有限学习工单 / 缩小范围 / 请求必要裁决
```

## 4. 目标循环：两个大循环都能套小循环

用户 Goal 和“完善天问”元 Goal 使用同一结构：

```text
父 Goal / Loop
├─ 当前阶段 Task
├─ 子目标 Loop：解决关键未知
├─ 子目标 Loop：验证候选方案
└─ 子目标 Loop：处理新发现的问题
```

区别只在目标对象：

- 用户循环改造用户指定的项目、流程、知识或产物；
- 元循环改造天问的 Skill、策略、记忆视图、路由和非关键 Harness 组件。

每个子循环必须拥有：

- 单一、有限的局部目标；
- 来自父循环的预算信封；
- 明确输入证据；
- 允许读写的目标对象；
- 停止条件和返回契约；
- 自己的 Task、Run、Action、Event 与 Checkpoint。

子循环不能通过创建更多子循环重置预算。父循环只读取子循环已持久化的终态和交付物。

## 5. 正式学习链

### 5.1 五层资产

```text
1. Event / Trajectory：实际发生的事实
2. Case：与一次问题或成功有关的结构化案例
3. Lesson：带条件、证据和反例的经验主张
4. Artifact Candidate：Skill、Policy、Prompt 或其他对象的候选版本
5. Capability：经独立验证、发布并在后续任务中继续成立的能力
```

关键约束：

- 模型反思只能生成 Case、Lesson 或归因假设；
- 同一任务重试成功不能证明形成了通用能力；
- 一次成功和一次失败都不能直接变成全局规则；
- 原始证据不可由摘要覆盖；
- 所有派生对象保留来源引用和转换版本；
- 不修改系统也可以是有效学习结果。

### 5.2 Lesson 的最小内容

```text
claim                 建议采用或避免什么行为
when                  适用条件
not_when              不适用条件和反例
evidence_refs         支持证据
counterevidence_refs  反对证据
confidence_basis      证据强度，不是模型自信
target_scope          可能影响的对象和版本
status                candidate / accepted / rejected / deprecated
```

生命周期状态不与冲突、过期、敏感、需复验等原因混在一个字段中。后者使用独立标记。

## 6. 学习触发与停止

所有 Run 都产生低成本信号，只有以下情形进入学习队列：

- 明确失败或目标未达标；
- 用户纠正或重复抱怨；
- 预测与结果明显不一致；
- 同类问题重复出现；
- 高风险事故或 `unknown` 动作；
- 意外成功且可能复用；
- 环境、工具或依赖变化；
- 当前 Goal 暴露关键能力缺口。

学习队列分三级：

1. **记录：** 只保存 Case 或候选 Lesson；
2. **正常学习：** 创建有限 Learning Job；
3. **止损调查：** 重大事故立即限制相关行为并启动调查，但永久结论仍需验证。

一个 Learning Job 必须回答：

- 要减少哪个具体未知；
- 哪些证据支持它值得处理；
- 允许修改哪个对象；
- 为什么不先修改其他对象；
- 用什么实验区分竞争假设；
- 预算和停止条件是什么；
- 成功、证据不足和归因错误分别怎样返回。

停止不是失败。边际信息增益过低、预算用尽、缺少前提、风险变高或没有可区分实验时，都应形成可恢复 Checkpoint 并结束当前 Learning Job。

## 7. 归因与最小修改层

### 7.1 五类故障位置

```text
目标/验收定义
→ 信息获取与上下文
→ 决策、路由与规划
→ 工具操作与执行
→ 结果验证与评测
```

归因顺序：

1. 确认真实结果，而不是只看模型总结；
2. 确认问题适用范围和复现条件；
3. 比较成功、失败或 Champion/Challenger 轨迹的最早有效分歧；
4. 同时保留多个竞争假设；
5. 优先设计一次只改变一个核心变量的实验；
6. 从最小影响层开始修复；
7. 无法区分时保留假设，不强行生成候选。

### 7.2 最小修复阶梯

从低到高尝试：

```text
补充一次任务上下文
→ 修正检索或适用条件
→ 修正 `repo_task` Skill
→ 修正路由或非关键策略
→ 修正非安全关键 Prompt / Harness 组件
→ 提议修改评测协议
→ 提议修改治理核心或顶层目标
```

越靠后，影响范围越大，验证与人类裁决要求越高。首切片只允许实际发布 `repo_task` Skill；检索、路由、Prompt、评测和其他策略只能形成研究建议。

## 8. 记忆与上下文

### 8.1 读取管线

```text
权威状态生成记忆需求
→ 硬过滤：用户、工作区、用途、权限、版本、时间
→ 结构化与全文检索
→ 适用条件、冲突和新鲜度检查
→ 生成紧凑证据包
→ 模型需要时再展开原始详情
```

每次都应提供的不是整个记忆库，而是：

- 当前 Goal 与不可变底线；
- 当前 Task 的验收条件；
- Run 冻结版本；
- 已批准和已拒绝的动作；
- 剩余预算；
- 当前阻塞和未结算 `unknown`。

第一版使用 SQLite、结构化字段和全文检索。向量数据库、知识图谱和自动跨用户相似检索延期。

### 8.2 记忆写入防火墙

模型不能直接写入正式记忆。写入提案必须经过：

- 用途与作用域检查；
- 字段白名单和长度上限；
- 来源与证据引用；
- 敏感信息和秘密扫描；
- 过期时间；
- 冲突与重复检查；
- 写入类型的权限检查。

网页、邮件、仓库文档和工具输出属于不可信外部内容。它们可以成为证据，但不能直接改变 Goal、用户偏好、权限、底线、评测或正式记忆。

记忆检索本身也要评测：至少比较“使用记忆”和“不使用记忆”的结果，检查错误检索、负迁移、越权和提示注入传播。

## 9. 自我模型：能力账本，而不是人格

天问维护条件化、按版本隔离的能力账本：

```text
能力类型
+ 任务与环境条件
+ 所需工具和权限
+ 已验证版本
+ 成功、失败、成本和预测误差
+ 已知限制与过期条件
```

模型对自己的信心只是一条弱信号。真正依据来自测试、真实结果、用户纠正、工具和权限清单、版本记录与长期统计。

当任务需要一项尚未证明的能力时，协调器从五种策略中选择：

1. 直接执行已证明能力；
2. 先做低成本能力探测；
3. 创建有限学习子循环；
4. 委派给有独立能力记录的外部 Worker；
5. 缩小范围或请求必要信息。

外部 Worker 的成功不自动等于天问获得了同样能力，也不转移最终责任。

## 10. 用户协作：证据化决策说明

控制面展示：

- 当前 Goal、阶段、Task 和版本；
- 已发生事实和产物；
- 当前公开假设及其证据；
- 正在验证什么；
- 下一步、预算和停止条件；
- 风险、不确定项与 Champion/Challenger 状态；
- 用户现在介入能改变什么；
- 用户不介入时 Agent 将怎样安全继续。

只有同时满足以下条件才阻塞询问用户：

1. 这是只能由用户决定的目标、价值、偏好或授权问题；
2. 没有安全、可逆且明显保留意图的默认动作；
3. 用户答案会实质改变下一步；
4. 现在询问的价值高于稍后批量询问。

否则优先缩小动作、在隔离环境探索，或发送非阻塞摘要。多个非紧急问题应合并成一次“决策包”，包含推荐项、影响和未回答时仍可继续的部分。

## 11. 元学习治理

### 11.1 元学习能改什么

元学习可以提出：

- `repo_task` Skill 候选；
- Skill 适用范围和检索规则候选；
- 非安全关键 Prompt 候选；
- 学习触发阈值或调度策略候选；
- 新评测案例和评测协议修订建议。

元学习不能自行修改：

- 顶层 Goal 和不可变底线；
- Action Gateway 与权限包络；
- 安全门槛；
- 隐藏保护集；
- 发布器与审计账本；
- 自己当前使用的成功定义。

### 11.2 修改评测的独立工单

评测协议由以下内容共同定义：

```text
任务集 + 评分器 + Harness + 工具 + 预算 + 环境 + 模型/参数
```

任一项改变都生成新的 `eval_protocol_version`。新旧协议至少进行一次桥接比较。新协议在独立批准前不能替换旧协议，也不能用于宣称当前 Challenger 已经超过 Champion。

评测数据分三层：

1. 开发集：学习者可见，可获得详细反馈；
2. 密封晋级集：学习者不可见，只返回汇总和失败类别；
3. 安全与对抗集：独立运行，候选不能选择、读取或修改。

候选必须同时满足效果提升和不可交易的安全下限。不能用单一总分让成本、速度或成功率抵消越权、泄露、过度拒绝或不可恢复风险。

密封评测和首次晋升都使用持久的一次性请求：请求先绑定候选、Champion、评测协议、随机挑战与过期时间；签名回执导入或用户确认时在同一事务内验证并消费，防止调用者伪造期望挑战或重放旧回执。

### 11.3 元策略的发布

学习调度器、检索器或评测辅助器的候选同样走：

```text
声明式提案
→ 不可变版本
→ 固定预算的影子运行
→ 旧协议保护评测
→ 小范围灰度
→ 晋升或回滚
```

调度候选不能减少自己的安全评测、跳过失败案例或改变报表口径来制造改善。

## 12. 隐私、用途与跨循环边界

首版是单用户、本地优先，不做跨用户学习。

用户循环与元循环的边界：

```text
用户原始数据
→ 用户/工作区私有证据
→ 字段白名单、用途检查、脱敏和最小化
→ 元循环可见的事件摘要
```

元循环默认不可见：

- 原始对话；
- 文件正文、路径和文件名；
- 命令参数和完整错误文本；
- 凭证、Cookie、令牌和恢复码；
- 截图、网页正文和检索片段；
- 原始模型思维文本；
- 用户身份和稳定可关联标识。

每个可持久化对象至少记录：

```text
scope / purpose / source_class / provenance_id
retention_until / sensitivity / authority
parent_object_ids / transform_version
```

删除需要沿来源关系传播到索引、摘要、缓存和尚未发布的候选。首版不把用户数据用于模型权重训练，因此不承诺对模型权重执行“机器遗忘”。

这是一项工程数据治理基线，不替代具体法域的法律合规评估。

## 13. 长期运行、崩溃与恢复

### 13.1 本地耐久模型

- Event 仅追加，`(run_id, sequence)` 唯一；
- Checkpoint 是从稳定边界生成的恢复快照，不覆盖 Event 历史；
- Action 记录真实副作用的完整生命周期；
- 每个 Run 冻结模型、Prompt、Skill、Policy、Harness、工具、权限和环境版本清单；
- 预算、重试、父子关系和租约全部持久化。

Action 的核心顺序：

```text
prepared
→ started
→ succeeded / failed / unknown
```

必须先持久化 `prepared` 和幂等键，再调用外部工具。调用已开始但结果未持久化时，恢复后进入 `unknown`。先查询外部状态或使用同一幂等键对账；无法证明时只暂停受影响分支，不能盲目重试。

### 13.2 单机租约

首版即使串行执行，也使用短租约防止两个 CLI 同时接管同一 Run：

```text
owner_id + lease_generation + expires_at
```

接管租约不表示旧执行一定没有产生副作用。新持有者先把 `running` 且没有终态的 Action 原子转成 `unknown` 并追加恢复 Event，再进行外部核对；完成以前不能推进任务。

### 13.3 SQLite 边界

第一阶段使用本地 SQLite、WAL 和短事务：

- 模型调用、网络调用和工具执行不放在数据库事务内；
- SQLite 只保证本地状态原子性，不保证外部系统“恰好一次”；
- WAL 适合单机，不作为网络文件系统或分布式高可用方案；
- 遇到 `SQLITE_BUSY` 使用有限重试和退避，不形成无限恢复循环。

分布式队列、跨机租约、事务 Outbox、Saga、PostgreSQL 和多 Worker 调度延期，直到单机真实负载证明需要。

## 14. 首版采用与延期

### 14.1 首版必须实现

- Goal/Loop/Task/Run/Action/Event/Checkpoint 权威状态；
- 两类大目标循环和有限父子 Loop；
- Run 版本清单、预算继承和单机租约；
- Action Gateway、动作幂等键、`unknown` 对账；
- Event → Case → Lesson → `repo_task` Challenger；
- 最小修改层归因；
- Champion/Challenger、开发集、单独身份启动的一次性评测进程持有的密封保护集、Ed25519 签名聚合回执、首次人工晋升回执和回滚；
- 用户/工作区/用途边界和元循环证据投影；
- 记忆写入防火墙和结构化/全文检索；
- 只记录条件化能力观察的最小能力账本与低成本能力探测；
- 证据化决策说明；
- 本地 CLI 和一个完整端到端演示。

### 14.2 首版明确延期

- 模型权重训练；
- 多用户云服务和跨用户学习；
- 自动改 Runtime、Action Gateway、评测门槛或发布器；
- 自动把评测协议新版本设为正式标准；
- 向量数据库和复杂知识图谱；
- 并发子 Agent 与外部 Worker 编排；
- 浏览器、真实账户和自动投递简历；
- 分布式数据库、队列、微服务与多机恢复；
- 完整桌面或 Web UI；
- 多候选种群搜索和自动 Harness 代码改写；
- `repo_task` 以外的 Skill、路由、策略或 Prompt 自动发布。

## 15. 主要反模式

- 把模型反思直接写成正式 Skill；
- 把一次成功或一次用户意见泛化为全局规则；
- 让候选读取或修改隐藏保护集；
- 让 Agent 修改评分器后用新评分器证明自己更好；
- 用户记忆和全局经验共用一个无强作用域隔离的向量库；
- 先收集全部日志，再承诺以后脱敏；
- 把网页、README、邮件或工具输出当成系统指令写入记忆；
- 从“当前最新版”恢复旧 Run；
- 把超时当失败并自动重试外部动作；
- 用新增子循环或新 Action ID 重置预算和一次性授权；
- 用一个综合分数抵消安全、正确性或用户负担退化；
- 为了展示“持续进步”降低晋升门槛。

## 16. 资料与设计依据

### 持续学习与自我进化

- [Reflexion](https://papers.neurips.cc/paper_files/paper/2023/hash/1b44b878bb782e6954cd888628510e90-Abstract-Conference.html)：语言反馈可形成后续尝试使用的候选经验，但不等于独立验证。
- [ExpeL](https://arxiv.org/abs/2308.10144)：从跨任务轨迹抽取可复用经验。
- [LifelongAgentBench](https://arxiv.org/abs/2505.11942)：连续任务中的保持、迁移和遗忘评测。
- [Reward Tampering Problems and Solutions](https://arxiv.org/abs/1908.04734)：评价通道与策略需要隔离，避免 Agent 通过改变奖励输入优化表面指标。

### 评测、治理与安全

- [NIST AI RMF Generative AI Profile](https://doi.org/10.6028/NIST.AI.600-1)：生成式 AI 的治理、评测、监控与风险记录框架。
- [OpenAI：Designing AI agents to resist prompt injection](https://openai.com/index/designing-agents-to-resist-prompt-injection/)：从不可信内容到危险能力的数据流与分层防护。
- [OWASP LLM Prompt Injection Prevention Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)：外部内容隔离、最小权限和高影响动作确认。

### 隐私与来源

- [GDPR Article 5](https://eur-lex.europa.eu/legal-content/EN/TXT/?uri=CELEX%3A32016R0679)：目的限制、数据最小化、保存期限和可证明责任。
- [NIST Privacy Framework](https://www.nist.gov/privacy-framework/privacy-framework)：隐私风险的工程治理框架。
- [W3C PROV-O](https://www.w3.org/TR/prov-o/)：实体、活动和责任主体之间的来源与派生关系。
- [NIST SP 800-88 Rev. 2](https://doi.org/10.6028/NIST.SP.800-88r2)：数据清理和不可访问性目标。

### 恢复与本地运行

- [PydanticAI Harness Step Persistence](https://pydantic.dev/docs/ai/harness/step-persistence/)：追加事件、稳定快照、工具效果账本和 `unknown_after_crash`。

- [SQLite Atomic Commit](https://sqlite.org/atomiccommit.html)：本地事务的崩溃原子性边界。
- [Python `sqlite3`](https://docs.python.org/3/library/sqlite3.html)：Python 事务和连接行为。
- [pyca/cryptography Ed25519](https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/)：使用成熟库对密封评测聚合回执进行非对称签名与验签。
